## 开发中：任务预览、执行效率与常用任务候选

当前 `etax-340-step1-foundation` 分支正在整合统一任务状态、通知三级入口、手动接管及息屏后台执行，配套引擎为 `20261102-e46-transition`。这是未发布候选，以上正式测试下载与历史版本保持不变。

2026-11-03 导航候选：加入旧后台工具可直接使用的返回入口、启动窗口未就绪时的输入拦截、结构化恢复指引及动态页面等待上限。详见[后台返回与启动恢复验收](etax/BACKGROUND_NAVIGATION.md)。

通知保留原生流体云样式及三个完成按钮；有后台应用时，点击通知进入临时的小预览，再点画面放大。只观看不会暂停任务；主动“接管”须等待当前操作结束。息屏时允许虚拟屏任务继续，锁屏期间不执行主屏操作。ColorOS 下的布局、输入法与深度休眠网络行为仍待匹配候选真机验证。详见[本次实现与验收说明](etax/TASK_PREVIEW.md)。

2026-11-02 候选返修：通知使用明确的小手机图标；预览首帧未到时显示手机占位。修复连续手动点击和完成页面接管被误判为“旧操作未结束”，接管时保留独立放大按钮，并加入本地点击波纹、滑动跟随轨迹。应用交还等待主屏窗口就绪后再释放旧画面，不为过渡强制重启 App。

后续 e43 返修：修复保留前台操作权时“让 AI 继续”没有解除任务暂停；恢复受阻时不虚报继续。预览区分 AI 执行中的只读状态和真正暂停，分辨率提高至小窗 640／大窗 960，通知图标改为可单色染色的透明手机轮廓。实时画面仍在点通知后的小窗中，不通过高频通知刷新模拟视频。

后续 e44 返修：应用移到主屏处理验证后，预览的“让 AI 继续”不再被已失效的旧预览阻断；修复运行时收尾绕过主屏窗口就绪确认、提前断开采集的问题。输入失败提示保留到下一次操作结果，不再被下一帧覆盖。美团验证页无响应的具体原因仍未确定，不能等同于已解决应用风控。

后续 e45 返修：运行中和暂停中的通知增加“打开 ETA 会话”独立按钮，通知主体仍打开预览。最后一个任务进入终态后撤掉运行彩边，旧前台操作记录不再让彩边残留，晚到的运行状态不能重新创建已关闭的完成卡片。虚拟屏最终回收时直接释放显示，再关闭本地采集缓冲，减少先关闭显示输出再删除显示的双重变化；ColorOS 实际切屏效果仍需匹配候选实测。

2026-11-02 三轮并行优化候选还加入：

- 读取与计数：固定统计时间范围，按重叠条目核对连续覆盖，减少普通任务对私有数据库和未知格式的无边界探索；原生观察已附图时不再重复读取。
- 通知查询：固定时间区间、稳定分页和现存匹配通知总数。通知记录并不等同于聊天消息，记录变化会要求重新查询。
- 执行统计：正常收尾后，在会话中展开查看本地准备、模型请求、工具、暂停及其他处理耗时，不新增模型请求、日志数据库或常驻服务。
- 常用任务：首页菜单保存名称和指令，可编辑、复制、删除、再次执行或添加桌面快捷方式。每次复用当前模型开启独立会话；原会话的通知续接保持原样。

本次功能与验证边界见[效率优化和常用任务说明](etax/EFFICIENCY_AND_COMMON_TASKS.md)。沿用 e45 引擎，未改系统 Hook；不保证所有模型遵从策略，也不预先承诺提速比例。

2026-11-02 通用操作反馈候选：动作前监听短提示，节点无法确认时附有限历史画面；区分动作接受与业务结果，抑制同一目标跨节点/坐标/长按的无进展重试，补充稳定后的文本回读与键盘状态。前台和后台共用规则，不针对单个 App。详见[实现与验证边界](etax/ACTION_FEEDBACK.md)，新候选仍待真机反馈。

e46 返修候选补充前台截图坐标生命周期与键盘/窗口变化校验，纠正后台窗口暂缺的错误语义，并延后最近任务交还时的旧显示回收。详见[坐标与交还说明](etax/COORDINATES_AND_HANDOFF.md)；ColorOS 闪烁改善仍须手机验证。

常用任务现已接入 Agent 原生工具：可在对话中保存、查找、读取、修改和删除流程，与任务页面和桌面快捷方式共用数据。指令正文按需读取，不注入整个任务库；压缩重复提示和路由说明，保留用户自定义提示及前后台安全约束。[原生接入与提示词优化](etax/COMMON_TASK_AGENT.md)记录实现、输入量对比与测试方法；数据量减少不等于已测得相同比例的等待时间下降。

## 我们新增与改进的功能

| 功能 | Eta 后台版的实现 |
| --- | --- |
| 联网搜索与权限入口 | 内置必应搜索及 DuckDuckGo 备用来源、有界等待与错误分类；悬浮窗授权入口始终可点击，并兼容系统备用页面。 |
| 前后台选择 | 当前页面与当面操作使用前台工具；明确要求后台执行或续接后台任务时使用虚拟屏。 |
| 后台操作 App | Root 虚拟屏承载目标 App；每个任务独立管理屏幕、观察结果与输入状态。 |
| 操作核验 | 前后台能力统一登记；后台检查窗口就绪，滚动明确选择目标，区分动作提交与界面变化，并拦截重复无进展操作。 |
| 双任务与队列 | 最多两个任务执行、两块执行或保留中的虚拟屏；其他请求排队，同一 App 串行使用。 |
| 实时会话 | 长按电源键提交后即可在 ETA 会话看到运行记录，退出助手面板不取消任务。 |
| 原生任务通知 | 每任务独立状态卡、流式进度、暂停与停止；完成状态在原卡片更新。支持的系统可将其显示为流体云/Live Updates。 |
| 任务完成提示 | 任务结束时在原卡片上请求一次系统顶部横幅；提供“打开 ETA 会话”“打开 App”“继续指令”。可在外观设置关闭弹出提示，任务通知仍保留。 |
| 通知栏继续指令 | 原生内联输入直接提交到原会话，无需打开聊天；另有“打开 ETA 会话”入口。 |
| 完成后接管 App | 停止采集并保留页面，点击结果卡移动原任务；确认主屏窗口就绪、旧屏为空后释放，过渡中不重复启动。 |
| 横屏、截图与节点 | 统一屏幕身份、逻辑尺寸和方向；截图坐标带帧引用，错误原因可诊断；无节点页面可使用截图坐标工具。 |
| 助手界面 | 可在外观设置开关的边缘流光、助手面板退出与拖动过渡、会话阅读位置恢复。 |
| 主动切回前台 | 实际移屏后暂停对应任务，停止旧屏输入和自动拉回；其他任务不受影响，需用户手动恢复。 |
| 稳定性策略 | 创建失败回滚、超时后阻止堆积指令并要求重新观察；息屏暂停、解锁后手动继续，不为铺满屏幕强制重启 App。 |

上游 v3.3.5 的子智能体、独立子模型、过程详情、工具摘要和 Debian 环境恢复已合入。后台版仍限制两块虚拟屏；子智能体不能借用父任务的后台屏幕工具。详见[版本对比与更新记录](etax/README.md)。

## 使用与兼容性

- Android 13+、ARM64。后台虚拟屏操作需要 Root，并开启 Eta 的无障碍服务；模型服务由使用者配置。
- 设置系统默认数字助理后，可通过长按电源键唤起；具体入口取决于手机系统。
- 当前真机反馈主要来自 OPPO Find X9 Ultra / ColorOS 17。流体云布局由系统决定，其他 ROM 的通知与跨屏行为需要实测。
- 已完成页面与执行页面合计最多两块，容量不足时可能回收已完成页面。Android 内存回收、游戏自身行为或跨屏配置变化仍可能导致第三方 App 重建；不承诺所有游戏都能无缝接管。
- 早期息屏执行曾撤回；当前集成候选已允许后台虚拟屏继续执行，锁屏时仍保护主屏，深度休眠联网须实测。早期“三屏、第四项替换最早任务”和“一分钟销毁已完成屏”也已替换，当前规则以上表为准。

## 源码与测试

Android 应用位于 `app/`；后台桥接在 `app/src/main/java/com/eta/shadow/`；Root 引擎在 `etax/engine/`，共用几何与操作证据协议在 `etax/shared/`。`app/src/test/` 保留上游和后台版回归测试，`etax/engine/tests/` 覆盖引擎部署脚本，防止并发、生命周期、通知回复、输入核验与部署问题回归。
