# Eta 后台版：源码导航与版本更新记录

本分支基于 [蛮吉（Mangi-11）的 Eta](https://github.com/Mangi-11/Eta)。项目介绍、当前功能与许可证见[首页](../README.md)，编译及签名步骤见[构建说明](../.github/RELEASING.md)。

## 开发基线

`main` 就是最新版本，后续开发（包括 Codex 等协作者）直接基于 `main` 进行；`etax-340-step1-foundation` 等集成分支的内容已全部合入 `2026110501`，不再作为开发基线。每次发版在 `main` 上递增 `versionCode`（`yyyyMMdd` + 两位当日序号）、在需要时更新 `VDrive.java` 的 `BUILD`，并在下方“版本更新记录”最前面写一条版本说明；`main` 的签名构建成功后会自动发布 GitHub 预发布版本。

引擎源码通过 javac + D8 编译为 APK 内的 `vdrive.dex`，版本从 `VDrive.java` 提取。无障碍服务连接或首次调用后台屏工具时，App 使用 `su` 部署并启动引擎；版本及文件摘要不一致时更新。未授权 Root 无法使用后台虚拟屏。

**当前行为以首页及最新版本说明为准。** 下方记录各版本当时的实现，包括已撤回的实验；并非这些策略同时生效。当前版本最多两项执行、两块执行/保留屏；虚拟屏任务在主屏息屏时继续执行，锁屏时拒绝前台操作；通知可打开预览、手动接管与内联续接，完成后保留页面直到接管、显式释放或容量回收。

## 完成提示使用说明

从 `2026102902` 起，可在“设置 → 外观 → 界面与效果 → 任务完成时弹出提示”控制任务结束时的顶部横幅。默认开启；关闭只停止弹出提示，原任务的状态栏图标、下拉通知和操作入口仍保留。完成、停止和失败分别显示对应状态。

| 入口 | 操作结果 |
| --- | --- |
| 打开 ETA 会话 | 进入该任务对应的会话，查看完整执行过程和结果 |
| 打开 App | 打开该任务的目标应用，使用现有后台页面接管路径；没有目标 App 时不显示此按钮 |
| 继续指令 | 直接在通知中输入并发送到原会话，无需先进入 ETA 会话页面 |

如果下拉通知里有任务结果，但没有顶部横幅：

1. 确认应用内“任务完成时弹出提示”已开启。
2. 从“设置 → 后台任务通知”进入系统通知设置，允许 Eta 后台版通知，并允许“任务完成提示”类别显示横幅；系统勿扰设置也可能限制弹出。
3. 在手机亮屏且已解锁时新建一个简单任务复测。已结束、已划掉的任务不会因重新开启开关或解锁而补弹。

顶部横幅和流体云的动画、停留时间及按钮展开方式由系统控制。默认不发声、不振动。ColorOS 17 的具体展示仍需真机验证；该功能首次发布的验证结果见[2026102902 版本记录](#release-2026102902)。

### 2026111401 · 合入上游 Eta 3.4.x 新功能（3.3.5）

按功能挑选上游 3.4.0–3.4.4 的改动，用三方合并接进来；遇到冲突时保留我们的界面和后台引擎，只取上游的逻辑。

- **从回复分支出新对话**：回复的长按 / 更多菜单 →「在新对话中分支」，带着到这条为止的上下文另开一个对话，原对话不变。

- **本机工具逐项开关**：工具列表每个工具都有开关；关掉的工具不会提供给模型，误调用也会被拒绝。

### 2026110603 · 修复首页对话无法向下滑动（3.3.5 后台版）

阶段 3（2026110602）的真机验收发现：会话里可以往上翻看旧消息，但往回滑看新消息时手指上划没有反应。

- 原因：首页改用自绘顶栏后，外层页面仍挂着旧顶栏的折叠滚动处理。这个处理要由 Miuix 顶栏测量后才有折叠上限，自绘顶栏不会测量它，上限一直是“无限”，于是每次手指上划都被它当成“收起顶栏”全部吃掉，列表收不到。
- 修复：只有真正使用壳层 Miuix 顶栏的页面才挂这层滚动处理；首页（自绘顶栏）不再挂。其他页面行为不变。
- 新增 `AgentAppShellScrollTest`：用真实手指拖动首页列表，验证上划向前、下划回退、再上划仍可向前。原有长会话测试直接驱动列表、绕过了这条链路，所以没能发现。

### 2026110501 · 统一操作、任务预览与接管、网页增强、观察提速（3.3.5 后台版）

本版把 `etax-340-step1-foundation` 上的全部开发合入 `main` 并正式发布，配套引擎为 `20261105-e49-parallel-observe`。包名与签名不变，可直接覆盖安装。

**主要变化**

- **统一操作**：前后台共用一套原生 GUI 工具，用 `execution_location=background` 选择任务自己的后台屏；公开的重复 `screen_*` 工具与文本输入别名已移除，引擎内部协议保留。
- **任务预览与手动接管**：点击运行通知打开小预览，可放大、接管（点击、长按、滑动、返回）后交还 AI；通知增加“打开 ETA 会话”。任务状态统一，终态提交后才显示完成。
- **息屏**：虚拟屏任务不再因主屏关闭一律暂停；锁屏时拒绝前台操作，已有的手动暂停不会自动恢复。

- **引擎**：e47 系统服务失联后的回收与准确诊断；e48 后台触摸不迁移主屏输入法焦点；语音停止更及时。

**本次发布新增**

- **观察提速**：`observe_screen` 同时需要节点树和截图时，两者并行读取，不再先后等待。引擎只在执行中的命令是截图时放行节点的几何校验，输入类操作仍须等截图结束；节点与截图仍做同屏几何一致性校验，不一致时要求重新观察。
- **修复 Runtime 绑定丢失**：排队的绑定请求若从未执行，会重新排队，而不是让后续每次调用干等 8 秒超时。该问题曾导致回归测试偶发 10 秒超时。
- **引擎认证 token** 每个进程只读一次，不再在每个请求上加跨进程文件锁读文件；文件被删除时以同一 token 恢复，保持与引擎配对。
- **构建**：PR 检查与签名构建合并为单一工作流（测试 → 签名构建 → 发布），测试只运行一次；只改文档或鸿蒙目录不触发构建；`main` 签名构建成功后自动发布 GitHub 预发布版本。

- 活跃任务每 30 秒续期；App 进程消失后引擎回收过期会话。正常 `screen_finish(mode=notify)` 可继续停留最多一分钟，后续任务优先回收这些已完成的屏。
- 每个活动任务有独立系统实时通知，分别显示流式进度、打开聊天、暂停及停止；旧 Android 仍可使用 App 胶囊。支持系统允许的 promoted ongoing 显示。频道为静音 DEFAULT 频道；系统通知权限和 ColorOS 状态栏/流体云布局仍由系统管理。
- 边缘流光复用官方组件，亮屏绘制、息屏移除窗口；后台展示不申请保持屏幕常亮。

引擎协议增加 `sessionId`、`keepalive`、`validate`、`release_session`。无会话标识的 MCP 请求继续使用独立的兼容会话。`release_session` 的成功响应代表清理已确认，不能以网络超时推断已释放。设备动作可能已经发生，重连只恢复记录，不自动重放操作。

相关回归测试：`ScreenLeaseRegistryTest`、`AssistantRunRecoveryTest`，以及 Runtime 会话、恢复、通知和浮层测试。虚拟屏输入焦点、后台运行及 ColorOS 流体云表现需要在真实 Root 设备验证。
