## 开发基线

`main` 就是最新版本，后续开发（包括 Codex 等协作者）直接基于 `main` 进行；`etax-340-step1-foundation` 等集成分支的内容已全部合入 `2026110501`，不再作为开发基线。每次发版在 `main` 上递增 `versionCode`（`yyyyMMdd` + 两位当日序号）、在需要时更新 `VDrive.java` 的 `BUILD`，并在下方“版本更新记录”最前面写一条版本说明；`main` 的签名构建成功后会自动发布 GitHub 预发布版本。

## 完成提示使用说明

从 `2026102902` 起，可在“设置 → 外观 → 界面与效果 → 任务完成时弹出提示”控制任务结束时的顶部横幅。默认开启；关闭只停止弹出提示，原任务的状态栏图标、下拉通知和操作入口仍保留。完成、停止和失败分别显示对应状态。

| 入口 | 操作结果 |
| --- | --- |
| 打开 ETA 会话 | 进入该任务对应的会话，查看完整执行过程和结果 |
| 打开 App | 打开该任务的目标应用，使用现有后台页面接管路径；没有目标 App 时不显示此按钮 |
| 继续指令 | 直接在通知中输入并发送到原会话，无需先进入 ETA 会话页面 |

如果下拉通知里有任务结果，但没有顶部横幅：

1. 确认应用内“任务完成时弹出提示”已开启。
2. 从“设置 → 后台任务通知”进入系统通知设置，允许 Eta 后台版通知，并允许“任务完成提示”类别显示横幅；系统勿扰设置也可能限制弹出。
3. 在手机亮屏且已解锁时新建一个简单任务复测。已结束、已划掉的任务不会因重新开启开关或解锁而补弹。

顶部横幅和流体云的动画、停留时间及按钮展开方式由系统控制。默认不发声、不振动。ColorOS 17 的具体展示仍需真机验证；该功能首次发布的验证结果见[2026102902 版本记录](#release-2026102902)。

### 2026111642 · 去掉磨砂只留液态玻璃，弹窗回到小窗，小米上过渡更顺（3.3.5）

**弹窗回到小窗**：2026111635 起点开设置项、选项列表弹出的是 COUI 底部半屏面板（贴底、带拖动条）。现在换回之前的小窗：居中的圆角卡片，背后模糊，底部一个「关闭」，点外面或返回键也能关。全 App 用这种弹窗的地方一起换回。

**去掉 COUI 17 磨砂**：外观里的「控件材质」选项去掉了，对话页顶部按钮、输入框、侧栏底部栏只用液态玻璃。之前选过磨砂的会自动回到液态玻璃。

**小米 17 Max 上点开时卡一下**：没有真机，我按代码找了两个最可能的原因，都改了：
- **刷新率**：小米 HyperOS 的动态刷新率默认把第三方应用压在低档，手指一碰才临时提到高刷，过渡动画正好落在切档那一下，看起来就顿。OPPO 没有这个限制，所以没发现。现在外观里多了「界面始终用最高刷新率」：打开后胖小胖的窗口固定请求屏幕最高刷新率（同分辨率下最高的显示模式），离开胖小胖就交还系统。**小米上默认打开**，其他手机默认交给系统；耗电会略增，可以自己关掉对比。
- **弹层背后的整页记录**：以前只要开着背景模糊，弹层宿主每一帧都把整个界面多录一遍，给弹窗、菜单的背景模糊用——没有弹窗的时候也在录，点开页面、过渡动画时这份开销一直都在，高分辨率屏上更明显。现在只有用到整页模糊的弹层（对话框、小窗、菜单、下拉列表）挂在界面上时才录，收起后停止。

**如果还卡**：外观里先把「背景模糊」关掉试一次，能分出是不是模糊造成的；再打开「设置 › 渲染诊断」，做几次卡的操作后截图发我（帧数、超时帧、采样源）。

**测试**：小窗的点外面关闭 / 不允许关闭 / 关闭完成回调、整页记录的登记与撤销（两个弹层先后出现和消失）、刷新率模式选择（只选同分辨率最高档、只有一档时不指定、用户选择优先）；真机模式弹窗截图确认是居中小窗；去掉了磨砂的对比测试。

### 2026111641 · 长按电源键按机型适配（ColorOS / HyperOS / 通用），锁屏时自动改用后台屏（3.3.5）

你换到小米 17 Max（HyperOS 4.0.4，安卓 17）后反馈两件事：长按电源键唤起用不了；做任务时主屏一锁就提示「主屏已锁」，什么都打不开。

**长按电源键：按手机分别适配**
- 设置 › 长按电源键唤起 里多了「适配方式」：**自动**（默认，按厂商、品牌和系统属性识别）/ **ColorOS**（OPPO、一加、realme）/ **HyperOS**（小米、红米、POCO）/ **通用**（系统默认助手）。认错了可以手动选；已经配置过的要先「恢复原配置」才能切换。
- **HyperOS 怎么做**（都要 Root，都先备份原值、可以一键恢复）：把胖小胖设为默认数字助理；把小米的「长按电源键」动作（系统设置 `long_press_power_key`）从唤醒小爱改为呼出默认数字助理（`launch_google_search`）；AOSP 的 `power_button_long_press` 设成 0，免得两边都响应；语音识别服务固定为小米自带引擎——不这样的话 HyperOS 开机时会把语音助手重置回小爱。做法来自社区实测，不同 HyperOS 版本可能有差别，所以配置后仍要实际长按确认。
- HyperOS 要是把长按改回了小爱（常见于重启后），窗口里会写明，并出现「重新应用」：先恢复原配置再按当前适配重新配置一次。
- ColorOS（一加 PMA110）照旧走厂商长按广播；其他 ColorOS 手机和别的品牌走通用的默认助手。
- **为什么小米上报「ColorOS 策略接口未完成操作」**：从一加换机时，配置备份被一起搬到了小米上，胖小胖看到 ColorOS 的备份，就去调一加的接口。现在会识别出从别的手机带来的备份并作废（那些原值在这台手机上从没生效过），并提示一句；这几份备份文件以后也不再随换机或云备份迁移。新备份会记下是哪台手机建的。

**锁屏时任务不卡住**
- 原来主屏一锁，前台界面工具（打开应用、点按、观察等）都会被拦下，提示里只说「后台虚拟屏可继续」，模型不知道怎么转，任务就停了。
- 现在主屏锁着时，模型在前台打开应用（给了包名）会**直接改在后台虚拟屏打开**，并告诉它「之后的操作都在后台、不用等解锁」；后台也打不开时退回前台并说明原因。
- 其他前台操作被拦时，提示写清楚怎么转后台（`launch_app` 加 `execution_location="background"` 和包名，再重新观察）；没有 Root 时说明只能等解锁。

**测试**：新增 HyperOS 路线（配置、恢复、被系统改回、写入失败回滚、只接受普通设置值）、机型识别、ColorOS 备份是否本机、HyperOS 目标值（长按 0、固定识别服务、旧备份按当时的方式恢复）、换机备份作废与本机备份保留、锁屏自动转后台（成功、后台也失败、未锁屏或无 Root 不转）。

### 2026111640 · 电脑会话补齐：分支、重新回答、编辑重发、命令（3.3.5，插件 0.6.0）

你说电脑会话的功能不够，比如分支会话用不了。这一版把手机对话有、电脑会话缺的一起补上，另外修了两个问题。**电脑上的 dsh-bridge 插件要更新到 0.6.0**（`git pull` 后从托盘完全退出 DeepSeek Harness 再打开）；插件没更新时，下面这些入口会提示更新，其余功能照旧。

**电脑会话新增**
- **分支会话**：长按一条回复 →「分支」，从这条回复所在轮次的结尾切出一个新会话，和桌面「分支」按钮同一个切点；新会话叫「原标题 (1)」，沿用原会话的模型，原会话不变，打开后按返回回到原会话。只有桌面也能分支的回复上才有这个入口（中途调工具前的过渡回复、出错的轮次没有）。会话面板里也有「分支会话」，切在最近一轮结束处。
- **重新回答**：点回复下面的「重新生成」，在新分支里把开启这一轮的那条消息（连同图片）重发一遍，原会话里的回答保留。电脑的记录不能改写，所以用分支实现。
- **编辑重发**：长按自己的消息 →「编辑」，和手机对话一样在气泡里改；点「编辑重发」时从这条消息之前切出分支，在分支里发改好的内容。取消就什么都不会发生，不会白建分支。
- **出错重试**：上一轮出错时，输入框上方出现「上一轮出错了 · 重试」。电脑上的 DSH 支持就原地接着做；不支持（实测 0.2.2-rc.1 不支持）就重发上一条消息并提示。
- **斜杠命令**：输入「/」列出电脑上这个会话能用的命令（实测有 `/compact`、`/goal`、`/plan`、`/permission`、`/export`、`/feedback`），点一条填进输入框。发送「/命令」时在电脑上执行、不发给模型；电脑没有这个命令时按普通消息发。命令和结果在对话里显示成一行小胶囊（「/compact · 已完成 / 失败」，点开看详情），桌面上执行的命令同样会显示。
- **压缩上下文**：会话面板里「压缩上下文」，以及上下文占用里的压缩入口，都是在电脑上执行 `/compact`。
- **导出**：回复菜单里的「导出」、会话面板里的「导出为 Markdown」，先把电脑上更早的记录取回来，再按手机对话的格式存成文件。
- 回复菜单里不再有「删除」（电脑的记录删不了，以前点了只会提示不支持）。

**修复**
- **手机发到电脑会话的图片，点开是黑的**：看图器只认手机本地图片，电脑会话里的图片地址是向电脑取图的 `dsh-image:`，看图器解不出来就是黑屏。现在点开时向电脑取原图（缩略图取过的直接复用），保存、分享也用原图；取不到时写明「没能从电脑取回这张图片」，不再是一片黑。
- **权限健康里引擎的「重新检查」点了没反应**：原来这个按钮只读一次引擎状态，不会启动引擎，而引擎平时要等后台工具第一次用到才启动，所以怎么点结果都一样。现在没就绪时按钮会真的做事：没有 Root →「去开启 Root」（跳到 Root 授权）；有 Root →「启动引擎」，用 Root 部署并启动，按钮显示「正在启动…」，结束后提示「后台引擎已就绪」或没启动起来的原因，并重新检查。

**插件 0.6.0（dsh-bridge）**
- 新操作：`sessions.fork`（按事件序号切分支，标题和模型照桌面的做法）、`sessions.retry`（DSH 的空消息续跑）、`commands.list` / `commands.run`（DSH 的命令服务，结果 5 分钟内返回）。
- 推送里多了命令事件：`command/run`、`command/done` 转成提示条目（`code: "command"` / `"command_done"`，用 `id` 配对）。
- 在本机 DSH 0.2.2-rc.1 上实测：分支（含「原标题 (1)」改名）、命令列表、`/goal`、`/compact`（本地假模型总结失败，失败结果也正确回到手机）、未知命令报错；重试在这个版本返回 `unsupported`，手机改为重发。

**测试**：插件 47 项（新增 5 项）；手机新增分支切点 / 重新回答 / 编辑 / 重试 / 命令合并 6 项单测，回复菜单（有分支、无删除）、看图器取电脑图片（成功与失败）、引擎按钮（无 Root 去授权、有 Root 去启动）界面测试。

### 2026111639 · 息屏时叫醒后台屏（3.3.5，引擎 e52）

按你发来的《息屏后台虚拟屏排查报告》（2026-11-24，三星 SM-S9180，吉利银河签到）修的：**息屏时后台虚拟屏用不了**——手动打开、复用会话、定时任务三条路都失败，日志里是 `atms launch failed (SecurityException: Not allowed to start activity …)`，退到 `am start --display` 后窗口没有画面。

**原因（按源码核对后的判断）**
- 报告的现象和证据都对，但引擎那 4 条改法里：「`resumeCapture` 早退」不成立（摘面时 reader 同时被清空，下次会重新挂面；亮屏复用立刻 `ready:true` 就是证据）；「闲置别收面」「交接别放弃」和息屏无关；「任务前唤醒主屏」方向对，但会让每次定时任务都点亮手机。
- 更可能的原因：后台屏建的时候带了 `OWN_DISPLAY_GROUP`（上游也一样），有自己的电源状态。手机息屏时它跟着睡下，系统就不让应用在上面启动、已有窗口没有画面；按电源键只叫醒主屏，后台屏不一定跟着醒。

**现在（引擎 `20261124-e52-bg-screen-wake`）**
- 给后台屏发命令前先看它醒没醒；没醒就**只针对后台屏**依次试：后台屏自己的「开显示」、按屏幕编号开显示、在后台屏上按下再取消一次（不会点到东西）。每试一种等一会儿看结果。
- 系统拒绝在后台屏上启动应用、或启动后窗口没有画面时，也会先叫醒再试一次。
- 任务期间给后台屏记「有操作」，防止中途超时睡下。
- 都叫不醒时，按新设置「息屏时后台屏醒不过来」（设置 › 运行期间保持屏幕常亮 下面）处理：**不点亮屏幕** / **只对定时任务点亮（默认）** / **所有任务都点亮**。点亮后任务期间保持（暗亮度），任务结束放开，屏幕按系统设置自己熄灭。不允许点亮时任务会直接告诉你「手机息屏，后台屏没能唤醒」，不会反复观察。
- 每一步写进 `vdrive.log`：后台屏 / 主屏 / 电源组状态、哪种方式起作用、主屏有没有被连带点亮；第一次需要唤醒时还会把系统里相关的隐藏接口名字记下来。

**需要你帮忙**：我这边没有真机，这几种方式在三星上哪种管用要实测。装上后息屏跑一次定时任务（或者息屏后让它在后台屏打开一个应用），把 `/data/local/tmp/eta/vdrive.log` 发给我，我据此定最终方案（比如只留管用的那种）。

### 2026111637 · 液态玻璃和 COUI 17 磨砂对比版（3.3.5）· 14 号方案 14.4c 第二段（试用）

### 2026111634 · 修通知卡在「运行中」、后台点不动自绘控件、刚打开应用时白白失败（3.3.5，引擎 e51）

按你发来的后台执行截图（「后台打开高德地图，看一下到万达要多久」：41 步、9 个失败、2 分 37 秒）和通知卡住的反馈修的。

**通知卡在「运行中」，要手动点「停止」**
- 原因：Android 16 上运行中的任务卡片是实况通知（流体云）。任务结束时把同一条通知原地改成「已完成」，ColorOS 不会收起被改回普通的实况通知，旧的「运行中」就一直挂着；点「停止」能消失，是因为那条路会把通知直接撤掉。2026111620 修过一次（完成卡换新编号），后来为了让「已完成」落回同一条通知又改回了原地更新，问题就回来了。
- 现在：编号不变（一个任务仍然只有一条通知），但从实况变成已完成时**先撤掉再重新发**。前台那条、停前台时、换前台卡片时三个地方都按这个规则处理。

**后台点高德的路线、结果列表没反应**
- 原因：后台屏上点坐标时，引擎先用无障碍「点击」那个位置的控件（这样不会把你正在用的键盘抢到后台屏）。高德的路线面板、结果列表是自绘控件，接受了无障碍点击却什么都不做，引擎也就当作点成功了，不会再试真实触摸。
- 现在：无障碍点击后 0.5 秒内页面没有任何变化、而且点的不是输入框，就在同一位置补一次真实触摸。输入框照旧只用无障碍点击，不抢键盘。引擎版本升到 `20261123-e51-tap-touch-fallback`，下次连上无障碍时自动更新。

**刚在后台打开应用就观察，连着失败**
- 原因：应用刚启动、还没把窗口交给观察服务时，读界面会返回「观察服务尚未提供窗口」，模型只好「等 3 秒 → 再观察」来回几轮，有时还去跑终端命令查进程。
- 现在：程序自己最多等 4 秒（每 0.25 秒看一次），窗口一出来就继续；等过窗口的话顺带重新截图，不用启动画面。超过 4 秒还没有才把原来的结果交给模型。

### 2026111624 · 后台提示可选「顶部光条」；流体云挡住摄像头光圈的原因（3.3.5）

- **新的运行特效：顶部光条。** 设置 › 外观 › 运行时屏幕流光选「智能」后，下面多了「后台干活时」：**摄像头光圈**（原来的）或 **顶部光条**。顶部光条是屏幕最上沿一道细光，两团亮光从顶边正中（摄像头、流体云那里）同时向左右流出去，2.4 秒一次。AI 在操作你的屏幕时仍是四周细光，开始、结束的提示不变；电脑任务的流光也跟这个选项走。
- **和屏幕圆角怎么不冲突**：光条不是一条独立的直线，而是「整圈流光」那条按屏幕圆角画的边缘路径的上沿一段——中间贴着顶边，两端顺着左上、右上角的圆弧往下走大约 45°；亮度在圆弧里从 0 渐亮，过了圆角再走 28dp 才全亮。所以不会画成一条被圆角切掉的直线，角上也没有生硬的端点；流动的亮光走到圆角时也跟着淡掉。没有圆角的屏幕就在两端各淡出一小段。
- **为什么流体云展开时摄像头光圈只剩上下两截**：光效窗口的层级取决于胖小胖的无障碍服务有没有开。开着时用无障碍浮层，层级在状态栏、流体云之上，光圈压在流体云上面（以前看到的样子）；没开时退回普通悬浮窗，系统把它放在状态栏、流体云下面，流体云一展开就把光圈中间挡住。顶部光条贴着最上沿，在流体云上方，两种层级下都不会被挡住。「摄像头光圈」选项的说明里也写了这一点。
- 测试：`AmbientGlowTest` 加两条（只有智能模式的后台干活才用光条，操作屏幕和「整圈」仍是四周细光；光条两端在圆弧里为 0、过了圆角全亮、左右对称、没有圆角时两端也淡出），画面帧加三张（光条刚冒出、正在流、流到两端，上面盖一个展开的流体云）。

### 2026111623 · 后台执行少走冤枉路，修思考用时越显示越长（3.3.5）

按真机反馈（后台用高德查医院距离，过程截图 + 最后的回答）改。那次的过程：点院区卡片和导航箭头，页面都「没变化」；再点被防重试拦下（`NO_PROGRESS`）；接着按返回又被拒（`BACKGROUND_OBSERVATION_REQUIRED`）；交卷前复核又专门重新观察、再按一次返回，最后的回答还以「复核完成：那条 press_key 报错……」开头。对应的原因和改法：

- **修：思考用时越早的越长。** 过程里「思考已完成 · 用时 148 秒、137 秒、127 秒……」从上往下递减、相邻差十来秒——其实每轮只有十来秒。原因是每到下一轮、整个运行结束，都会对这次运行的全部思考块「收尾」一次，已经结束的块也按「现在 − 开始」重算用时。现在思考块结束那一刻用时就定格，之后不再重算，也不再把你展开的块重新收起。之前存下来的对话里已经算错的数字不会变。
- **动作后的回看没读成时再读一次**：页面正在切换时读树、截图偶尔失败，以前这一步就没有 `after`，模型拿旧截图的坐标去点，被「后台输入必须先调用 observe_screen」拒掉（截图里「点击屏幕 · (300, 100)」那条）。现在隔 0.3 秒再读一次；还是不行就在结果里写明 `after_unavailable` 和「下一步先 observe_screen」。
- **被防重试拦下的点按，不再作废刚才的观察。** 以前后台每个动作提交前就先把观察作废，动作被拦下（明确没执行）也不恢复，下一步按返回只能先 `observe_screen`。现在后端明确说没执行时恢复原观察；说不清有没有执行的仍然作废。
- **返回、主页、最近任务键不看 `observation_id`**：它们不点任何元素，带了旧编号也不拦，只核对屏幕和应用没变；手上没有观察时程序自己读一次再按。回车可能提交表单，带了编号仍核对是不是最近一次观察。
- **点完页面没变时多等一下**：详情页、路线页常要联网加载，0.8 秒的回看还是旧页面，模型就以为没点上、再点、被拦。现在 `tap` / `tap_element` / `tap_area` 后页面没变，会再看两次（各约 0.6 秒），变了就立刻返回，结果里写 `late_change_checks`。只在界面树读得出内容（至少 6 个可读元素）时这样做；地图、游戏这类读不出的不等。
- **后台 `launch_app` 启动后自动看一眼**：等页面静下来（最多 1.5 秒）读一次树，`after` 里的编号下一步直接用。以前每个后台任务启动后都要专门跑一轮 `observe_screen`。
- **交卷前复核不再做无关的事**：复核提示改成先判断失败影不影响用户要的结果，收尾时的返回、关页面、观察编号过期这类没执行的动作不用再操作；答复照常先给结果，不提「复核」这件事，只有影响结果的失败才简短说明。
- 测试：`AgentRunMessageProjectorTest` 加一条（思考块结束后再收尾、运行结束，用时不变）；`TaskScreenSessionSpeedTest` 加四条（被拦下后按返回不用再观察、说不清的仍作废；启动后 after 可直接点、没观察时按返回自己读一次；点完慢加载的页面会再看、一直没变最多看两次；回看失败重读一次、两次都失败写明先观察）；`TaskScreenSessionTest` 里写死调用顺序的期望按新行为更新（启动后多一次等静 + 读树；返回键带旧编号不再被拒、回车仍被拒）。

### 2026111621 · 后台执行提速：11 号方案一次做完（3.3.5）

按真机诊断（后台小任务 253 秒、43 轮、失败 28%）定的方案，各期合在这一个版本里：

- **后台点完自动看一眼**：后台的点击、滑动、输入、按键做完后，等页面静下来（最多 0.8 秒，静了就继续），读一次界面，登记成新的观察放进结果的 `after` 里。以前后台每一步都要「观察一轮 + 动作一轮」，现在一轮。
- **只核对要点的那个元素**：动作前不再拿整页指纹比对。只核对屏幕几何和当前应用没变；点某个元素时在当前界面里重新找到同一个元素（类名、viewId、文字、描述一致，位置挪一点就点新位置），找不到或有两个一样的才拒绝。时钟、进度、角标、加载圈在变也照常点。坐标点：那个位置换成了别的内容（比如弹出对话框）才拒绝。
- **程序自己决定看树还是截图**（前后台都是）：界面树读得出内容就只给树；读不出（网页、Flutter、游戏这类，可读元素少于 2 个，或大块画布占屏四成以上而可读元素不到 6 个）就同一次顺带截图，结果里写 `screenshot_reason`。模型不用再先看空树、再要一次截图。
- **少走弯路**：后台的按键、往当前焦点输入框写字不再要求 `observation_id`，「输入 + 回车」「连按两次返回」可以同一轮发出；`type_text` 的 `submit`（写入后回车）和 `append`（读回现有文字再整体写入）后台也能用了；后台 `wait` 分段等（每段最多 1 秒），页面静了就提前返回并带上新观察，任务被停止时 1 秒内结束；后台 `wait_for_package` 能用了（看后台屏上的应用）。
- **改文件更快**：`edit_file` 以前要起 7 次 Shell（解析路径、取元数据、读、再取元数据、写前核对、写、写后取元数据），现在 3 次；`write_file` 从 3 次减到 2 次。安全性不变：写入时仍在同一次 Shell 里比对完整旧内容的哈希，被别人改过就不写、报 `FILE_CHANGED`。
- **运行诊断记下失败原因**：最近 20 次运行里多了 `failure_codes`（失败的错误码和次数，只记码）、`gui_rounds`（用到屏幕的轮数）、`observe_only_rounds`（只看不动的轮数）、`stale`（观察过期一类的失败）。下次导出诊断就能看出哪类失败最多。
- **系统提示**：删掉、合并了被这些改动淘汰的界面规则（「先查空树再补图」「节点工具必须带同一次观察的编号」等），工具说明里写明程序会自己决定截图、`after` 可直接用、后台哪些操作不支持。整体瘦身（7 千多字降到 4 千以内）要在真机上逐类对比，这版没做。
- 测试：`TaskScreenSessionSpeedTest`（11 条：after 可直接用、时钟变化不挡、目标挪动点新位置、目标消失或重复拒绝、坐标处换了内容拒绝、按键与焦点输入免编号、submit 按回车、append 读回、空树自动截图、wait 提前返回、后台 wait_for_package）；`AgentLocalToolsPermissionTest` 加前台空树自动截图；`ShellFileToolBackendTest` 加「改文件只起 3 次 Shell、并发改动不写」；`RunDigestTest` 加失败原因统计。既有后台测试里写死旧调用顺序、旧错误码的期望按新行为更新（旧编号仍被拒、动作仍不重放）。

### 2026111615 · 10 号方案第二期「工具报错讲人话」（3.3.5）

- 工具失败时，给 Agent 看的结果统一补上两项：**`retryable`**（原样重试有没有意义）和 **`hint`**（下一步该查什么，一句话）。比如文件找不到 → 先列父目录核对文件名和大小写；命令退出码 127 → 命令不存在，查安装和拼写；超时 → 可以重试一次，再超时就缩小范围；界面没准备好 → 等一下只重新观察，不要重复点击；能力不可用 → 不要原样重试，换方法或告诉你需要开启什么。工具自己给了提示的保留原样。
- **重复失败提醒**：同一次运行里，同一个工具、同样的参数第二次失败时，结果里加 `repeat_failures` 和一句「不要再原样重试，先排查或换参数」。只提醒，不拦截。

- 这些都在运行时统一加（`ToolFailureAnnotator`，接在 `AgentLoop` 拿到工具结果的地方），没有改任何工具本身的行为。和上一版的「交卷前自检」配合：复核时列给它的失败，现在都带着下一步该查什么。
- 测试：`ToolFailureAnnotatorTest`（补提示、成功与工具自带提示不动、第二次相同失败提醒而参数不同不算、参数键顺序不同算同一个）；`AgentModelClientLoopTest` 加一条（异常带类名、retryable、hint，第二次加重复提醒）。

### 2026111609 · 真机反馈：系统小更新后长按电源键失效（3.3.5）

### 2026111412 · 找到并修复手机对话空白的真正原因（3.3.5）

2026111407–11 手机对话（含新建）打开整页空白，侧栏和电脑会话页正常。09–11 三轮按「玻璃效果」猜测修改都没解决，这一版在本机用硬件渲染（与真机相同的 RenderNode 绘制）复现了空白，逐项排除后确认原因并修复。

- **原因**：COUI 模式下的弹出菜单（`EtaContextMenu`）为了收集菜单项，往所在的布局里放了一个看不见的 0 尺寸节点。侧栏里有一个长按菜单，这个节点被放进了侧栏外层的自定义布局；那个布局按顺序取「第 1 个是侧栏、第 2 个是对话页」，于是把这个空节点当成了对话页，真正的对话页（顶部按钮、消息、输入框）根本没有被摆上屏幕。电脑会话页不在这个布局里，所以正常；本机测试默认不走 COUI 菜单，所以一直没测出来。
- **修复**：菜单收集菜单项时不再往布局里放任何节点；侧栏外层布局把侧栏包成一个整体，侧栏内部再多出节点也不会挤占对话页的位置。
- **加了回归测试**：按真机模式、用硬件渲染截首页，确认对话页画出来；并确认菜单不在父布局里占位。去掉修复时这两个测试都会失败。
- **撤回 10、11 的误判改动**：首页顶部按钮和侧栏底部玻璃栏恢复 COUI 液态玻璃，顶栏恢复背后模糊。
- 输入框（09 起）：28dp 圆角矩形、玻璃上铺约 78% 表面色，保持不变。

### 2026110603 · 修复首页对话无法向下滑动（3.3.5 后台版）

阶段 3（2026110602）的真机验收发现：会话里可以往上翻看旧消息，但往回滑看新消息时手指上划没有反应。

- 原因：首页改用自绘顶栏后，外层页面仍挂着旧顶栏的折叠滚动处理。这个处理要由 Miuix 顶栏测量后才有折叠上限，自绘顶栏不会测量它，上限一直是“无限”，于是每次手指上划都被它当成“收起顶栏”全部吃掉，列表收不到。
- 修复：只有真正使用壳层 Miuix 顶栏的页面才挂这层滚动处理；首页（自绘顶栏）不再挂。其他页面行为不变。
- 新增 `AgentAppShellScrollTest`：用真实手指拖动首页列表，验证上划向前、下划回退、再上划仍可向前。原有长会话测试直接驱动列表、绕过了这条链路，所以没能发现。

引擎保持 `20261105-e49-parallel-observe`。阶段 3 的其余验收项不变，请继续按 [阶段 3 验证记录](design/validation/stage-3.md) 的清单在手机上检查。

- 每个任务独立卡片和控制入口，取消系统通知中的“切换任务”按钮。一个活动任务承担已有前台服务通知，其余独立发布；完成时在原通知 ID、图标和原生进度样式上直接显示“任务已完成”，不另发完成通知。终态事件立即刷新，不等待其他任务结束或后续归档回调；前台服务转交下一任务时先 detach，避免系统移除已完成卡片。
- 运行卡片打开对应聊天，完成卡片打开该任务最后成功操作的 App；无目标 App 时回退到聊天。保留最近三项完成卡片，新一批任务开始时清理旧完成卡片。用户取消的卡片不会被迟到的归档通知重新发布。普通流式更新每 750 毫秒合并一次，未变化卡片不重复发布。ColorOS 控制顶端胶囊数量及任务完成后的收起行为，应用无法指定系统布局。
- 已有执行服务持有可超时的 CPU 唤醒锁，覆盖模型等待与结果保存，结束即释放。虚拟屏使用独立显示组和 `ALWAYS_UNLOCKED`，只有确认显示组与主屏不同，才申请绑定该虚拟屏的显示唤醒锁；若 ROM 不支持，则记录诊断，绝不对主屏申请亮屏锁。该能力仍需在目标 ColorOS 真机息屏测试，不能用 JVM 测试保证 ROM 行为。
- 精简重复处理：通知选中状态字段合并为一份任务快照；屏幕心跳与清理共用三线程调度器；删除额外的完成屏巡检，交由已有巡检处理；状态复位统一在工具出口执行。正常回收从 150 毫秒开始确认，持续失败逐步退避，减少切换延迟与空转。启动及移屏等待支持及时取消。
- 诊断增加物理屏状态、执行 CPU 锁、虚拟屏独立供电能力计数及电池优化豁免状态；仍不记录聊天、密钥、截图或目标应用名称。

验收重点：完成网心云/滴滴后台操作时主屏无闪现；三任务各自展示进度，某项完成时原卡片立即更新且点击打开正确 App，其余任务继续；运行中锁屏后再唤醒查看新增步骤及结果；任务全部结束后释放电源和虚拟屏资源。

### 屏幕回收与兼容模式修复（2026102603）

该版本源码：[f229d13](https://github.com/Lmin2419/eta-background/tree/f229d13648ed02a851342fb360cbd9a6dd6bf759)。

- 屏幕关闭改为异步发起、确认后释放名额；失败后持续重试，不再三次失败就永久保留占用。`screen_finish` 成功即可交还应用所有权，无须等待模型回答结束。同一任务的屏幕操作串行，不同任务仍可并行；引擎明确返回启动前 `CLEANUP_PENDING` 时自动等待重试，超时或未知结果不会重放设备操作。
- 已完成的屏不再保持唤醒锁；亮屏时检查目标应用是否已回到主屏，及时清除虚拟屏配置。若同一个可见任务仍被系统标记为尺寸兼容模式，调用 Android 兼容重启按钮对应的 `TaskOrganizer.restartTaskTopActivityProcessIfVisible` 接口，清除旧兼容配置并重建界面，可能短暂重绘。普通全屏任务、隐藏任务及已换身份的任务不触发重建。ColorOS 的实际显示仍需真机验证。
- 截图改为保留最新原生图像，仅在请求截图时复制像素，避免逐帧复制整屏；完成时立即释放图像缓存。实际耗电变化未作真机测量。
- 首条任务检查点改为后台写入；执行和取消归档都等待该写入完成，保持记录顺序并避免取消后的旧记录复活。
- 显示等待应用、回收屏幕、打开应用、恢复显示及等待模型等状态。设置页可检查后台通知权限、跳转系统设置；通知被关闭时使用已有浮窗回退。
- 设置 → 关于 → 导出运行诊断：仅导出设备/版本、通知可用性、引擎会话数量、显示恢复结果及最多 120 条白名单状态事件；不导出聊天、截图、密钥、任务标识或目标应用名，用户选择本地保存位置。

补充回归覆盖：回收连续失败超过三次后的恢复、完成后让出同一应用、明确回收中响应的启动重试、兼容重建条件、首条记录与取消归档顺序、诊断字段过滤及通知关闭状态。

### 系统流体云与窗口恢复（2026102602）

该版本源码：[36d00ab](https://github.com/Lmin2419/eta-background/tree/36d00aba00067d2601c0b6ebf0692b3ff86f4480)。

- Android 16 QPR1 及以上只使用系统实时通知呈现任务，不再叠加 App 自绘胶囊或完成浮窗；边缘流光独立保留。旧 Android 版本继续使用原胶囊。
- 运行通知仍为同一个 ID `1107`。卡片内容跳转所选任务的聊天；多任务时提供切换、暂停/继续、停止当前任务。每个操作绑定不可复用的 run ID，迟到操作不影响后续任务。
- 流式更新同时刷新前台服务持有的通知快照，避免该快照一直停留在启动时的通用文案。单元测试确认只有一个通知记录；ColorOS 是否额外呈现普通通知须由真机复测，不能仅凭截图断言已消除系统层重复。
- `screen_finish` 只负责屏幕收尾，不再额外发布一条打开目标 App 的通知。最后完成的结果在前台服务释放后替换同 ID 的运行通知；已完成状态不继续申请系统实时活动。
- 点击/长按系统胶囊如何展开由 ColorOS 决定；点击其卡片进入聊天。系统可将同一实时通知同时呈现在状态栏及下拉区域，不能通过删除通知来保留其流体云。
- 应用显式移回主屏，或用户从桌面重新打开已停留在虚拟屏的应用时，清除该任务的窗口边界、应用边界、dp 尺寸和密度覆盖，恢复主屏全屏配置。使用 Root WindowContainerTransaction，不改手机全局分辨率、不强制停止第三方应用。ROM 不支持接口时记录失败并尝试清除像素边界；兼容缩放是否消失须由真机验证。
- 新增 `AgentSystemNotificationTest`，覆盖单一通知、聊天跳转不串任务，以及完成通知与前台服务退出的先后顺序。

系统接口参考：[Android Live Updates](https://developer.android.com/develop/ui/views/notifications/live-update)；[ColorOS 流体云操作](https://www.coloros.com/article/A00000075/)。

### 3.3.4 · 初版后台多任务（历史策略）

该版本源码：[ed86674](https://github.com/Lmin2419/eta-background/tree/ed8667454a3547c35affd14447b5df32cc46f73d)。

- 电源键入口提交后立即建立在途记录。App 用同一会话身份恢复已有事件并订阅后续事件；完成归档按 run ID 去重。关闭入口不取消任务，新一次唤醒拥有独立会话。
- `BackgroundScreenTools` 为每次运行绑定独立工具实例，`ScreenLeaseRegistry` 保留最多三个屏幕名额。同一应用等待当前所有者释放；不同应用并行。第四个不同应用需要屏时取消最早取得名额的任务，直到引擎确认旧屏清理后才分配新名额。
- `VDrive` 负责本地传输及有限容量的会话表，`VDriveWorker` 保留原引擎的 Android 操作实现。每个 worker 有独立 Handler、显示对象、输入状态、截图目录和清理状态。请求携带不可复用的 `sessionId`，已释放会话拒绝迟到请求。
- 活跃任务每 30 秒续期；App 进程消失后引擎回收过期会话。正常 `screen_finish(mode=notify)` 可继续停留最多一分钟，后续任务优先回收这些已完成的屏。
- 每个活动任务有独立系统实时通知，分别显示流式进度、打开聊天、暂停及停止；旧 Android 仍可使用 App 胶囊。支持系统允许的 promoted ongoing 显示。频道为静音 DEFAULT 频道；系统通知权限和 ColorOS 状态栏/流体云布局仍由系统管理。
- 边缘流光复用官方组件，亮屏绘制、息屏移除窗口；后台展示不申请保持屏幕常亮。

引擎协议增加 `sessionId`、`keepalive`、`validate`、`release_session`。无会话标识的 MCP 请求继续使用独立的兼容会话。`release_session` 的成功响应代表清理已确认，不能以网络超时推断已释放。设备动作可能已经发生，重连只恢复记录，不自动重放操作。

相关回归测试：`ScreenLeaseRegistryTest`、`AssistantRunRecoveryTest`，以及 Runtime 会话、恢复、通知和浮层测试。虚拟屏输入焦点、后台运行及 ColorOS 流体云表现需要在真实 Root 设备验证。
