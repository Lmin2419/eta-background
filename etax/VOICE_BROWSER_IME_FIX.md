# 语音停止、浏览器观察与主屏输入法修订

## 语音面板的方块按钮

原语音页和输入栏在 `RECOGNIZING` 阶段禁用了方块，键盘切换仍可用。现在录音时点击方块结束录音并进入识别，识别等待中再次点击可以取消；已有任务的停止动作保持独立。取消后迟到的识别或润色结果不得自动提交，已经显示的草稿保留。

同时调整状态发布顺序：先进入识别等待，再调用系统停止录音，避免同步返回的完成/错误被随后写入的“正在识别”覆盖。不改长按电源键配置或系统 Hook。

## 浏览器的跳转、首帧与元素查找

- 为页面维护文档代次。提交引发导航、旧 JavaScript 回执丢失时尽早返回 `SCRIPT_CONTEXT_CHANGED`，附当前页面状态和未知结果；不再为旧回执超时中止新页面。变更操作不自动重放，批次停在不确定步骤。URL、标题变化不是业务成功证明。
- 只读观察在文档更换后最多重试一次。新文档按需等待可观察内容，已就绪页面不增加固定两秒等待；仍未就绪返回 `PAGE_NOT_READY`。页面信息查询可用于空页面诊断。
- `onPageFinished` 不再冒充首帧绘制确认。已挂载 WebView 使用绘制回调；离屏 WebView 保留原绘制路径，明确标注 `offscreen_dom_only`。纯黑/纯白读取最多尝试三次、间隔 60ms，仍为空则返回待观察，不能将空白当作已取得正文；这也可能包括本来就空白的画布。
- 查找覆盖文档及开放的 Shadow DOM，返回可复用的路径与扫描范围、截断信息；不承诺穿透关闭的 Shadow DOM 或子框架。扫描有节点、根数量及时间上限。

报告没有提供百度百科具体 URL，因此尚未证明该站的零元素确实源于 Shadow DOM。HTTP 通道能访问而浏览器失败，也不足以证明两者出口不同；本轮不改网络出口或证书策略，不宣称解决所有网站验证。

## 后台点击与主屏键盘

后台触摸统一携带 Android 的 `FLAG_NO_FOCUS_CHANGE`，覆盖点击、长按、滑动及预览手动触摸的 DOWN/MOVE/UP/CANCEL。主屏触摸维持原行为，后台目标屏幕、坐标、归属与几何校验保留。

依据 AOSP，可信注入触摸保留该标记，InputDispatcher 因此跳过外部点击造成的焦点迁移通知；原通知可触发当前输入目标的失焦处理并收起键盘。这里没有强行恢复主屏焦点、隐藏/重开输入法、修改全局 IME 策略或重启第三方 App。

源码依据：[MotionEvent 标记](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-12.0.0_r1/core/java/android/view/MotionEvent.java)、[InputDispatcher](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/main/services/inputflinger/dispatcher/InputDispatcher.cpp)。真实 ColorOS 行为仍需手机确认，事件标记测试不能代替真机结论。

## 验证与手机验收

自动化覆盖语音物理触摸、识别同步/迟到回调、浏览器文档更换及取消、批次不重放、离屏首帧和六项后台触摸标记用例。真实 Chromium 本地页面验证开放 Shadow DOM 的查找/点击/输入、有限扫描、延迟内容和表单仅提交一次；Chromium 没有复现 Android WebView 回执丢失，后者通过确定性回归验证。

手机只需正常使用下核对以下三项，不要求重启、重新注入或制造故障：

1. 长按唤起后直接点方块；录音结束后若处于识别等待，再点一次应能取消。取消不能自动发出迟到的识别结果。
2. 浏览器提交普通搜索后观察结果，不重复提交；跳转后立即截图或查找，尚未就绪应给出明确提示，随后能取得内容。若再次遇到百科零元素，记录网址和错误码即可。
3. 主屏打开输入框保持键盘，后台操作计算器的数字按钮与滑动，检查主屏键盘是否保持、后台动作是否仍有效；需要时再测小窗手动接管。不要用真实发送、支付或绑定动作做回归。
