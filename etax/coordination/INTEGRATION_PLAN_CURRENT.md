## 3. 第三轮：统一任务状态

复用 AgentRuntimeSession.complete/cancel 的终态裁定及现有结果发布顺序，向会话、通知和预览提供同一份只读状态。沿用已评审设计，不新增独立状态数据库或第二套完成/取消仲裁。

实施接线：
- RuntimeRunRegistry / AgentRuntimeSession / AgentRuntimeWire：复用既有阶段、run 身份、结果和暂停原因；投影以无状态计算为优先。
- AgentExecutionService / AgentOverlayState / AgentOverlayText：从统一投影生成显示文案与按钮，通知展示/划掉状态不反向修改任务终态。
- TaskScreenSession：继续只管理执行位置、屏幕绑定和观察有效性。
- 新投影名称与字段按实际需要最小化；不为预览另造常驻服务。

完成标准：完成/取消竞争只有一个最终结果；提交过程中不提前显示完成；迟到回调不覆盖终态；重新打开会话与通知状态一致；取消 A 不改 B；划掉通知不会复活任务或补弹已划掉结果。

## 4. 第四轮：通知作为入口的三级预览

| 层级 | 用户看到什么 | 操作含义 |
| --- | --- | --- |
| 收起 | 原任务状态，右侧小手机图标或带手机轮廓的缩略图 | 查看任务概要；右侧位置以系统实际布局能力为准 |
| 展开 | 同一任务的小屏预览和状态 | 只看画面，不暂停 AI、不把点击注入目标 App |
| 再点预览 | 更大的画面视图 | 提供手动接管、继续 AI、打开 App 到主屏 |
| 关闭预览 | 回到原任务通知入口 | 停止额外预览刷新；AI 是否运行取决于既有控制状态，不因关闭窗口自动暂停或恢复 |

不再常驻第二条悬浮胶囊，不额外创建一条重复通知。两项任务分别保留通知和状态；预览窗口绑定选定任务。放大预览不等于把目标 App 移到主屏。

### 4.1 先确认通知承载能力

本分支 AgentExecutionService 使用 ProgressStyle 与 promoted ongoing。Android 官方 Live Updates 不允许自定义 RemoteViews，支持样式列表不含 BigPictureStyle。因此“大图通知能显示图片”不等于“同样布局仍能进入流体云”。

先验证两条呈现路径，形成一个可检查的结果：
1. **原生目标**：使用受支持的标准图片/图标字段或确有文档与权限支持的 ColorOS 接口，实现小手机缩略图及展开预览，同时保留实时通知资格。
2. **兼容候选**：若原生不支持，维持现有系统通知；用户点击后由临时 App 预览面板承接小画面，再点放大。不得将此描述为“全部嵌入原生流体云”。展示差异后再定交付形态，不默默牺牲流体云或增加系统 Hook。

原生通知的展开事件、尺寸及动画由系统管理；没有可靠可见性回调时，不能假定能获知通知被展开并启动高帧率采集。通知只使用已有帧的低频快照/状态更新，持续画面交互由具有明确生命周期的预览视图承接。不高频重发系统通知模拟视频。

验证项目：系统是否实际给予 promoted 状态、ColorOS 展示位置与展开结果、两任务不重复卡片、既有暂停/停止/回复可用。普通模拟器或 hasPromotableCharacteristics 返回值不能替代 ColorOS 实际展示验证。

### 4.2 通知身份与三个完成入口

- 保留每任务 notificationId、删除通知和完成提示去重策略。
- 通知内容/预览入口使用单独 PendingIntent 身份，携带 runId 与会话标识；打开时重新解析当前屏幕，不能只信任可能已回收复用的 displayId。
- “打开 ETA 会话”“打开 App”“继续指令”三个 action 原样保留；预览不占用第四个 action 挤掉它们。
- 原“打开 App”按钮继续走原页面交还路径；内容点击的预览与该按钮不能共用目标 Intent。
- 停止/失败且已无保留页面时明确显示画面不可用；不得为了展示旧预览重新启动第三方 App。锁屏沿用通知隐私策略。

### 4.3 预览帧与性能

- 借鉴 VirtualDisplayStageCard 的构图、留白、触摸反馈和展开动效，帧来源适配现有 VDrive。
- 预览帧使用独立引用，包含会话、显示身份、几何、旋转及采样时间；不覆盖模型已经收到的 observation_id/frame_id。
- 避免调用会刷新模型观察的 screen_shot 来驱动 UI；优先复用最新捕获帧，预览缩略图不持续写文件。
- 仅可见的大预览按预算提升刷新；隐藏、关闭、任务屏失效时停止额外消费者和编解码，丢弃过期帧并限制缓冲。
- 横竖屏按实际内容比例显示；点按坐标扣除留白，使用同一帧的几何转换，几何变化后拒绝旧输入。
- 遵守系统动画倍率，支持中途关闭和切换任务；动画完成不作为屏幕释放成功的证明。

### 4.4 手动接管、恢复与应用交还

正在执行的任务：
1. 查看/放大预览只读取。
2. 选择接管后，向该 run 请求暂停并等待当前操作实际退出；此时显示“正在暂停”，不接受穿透点击。
3. 确认任务、屏幕租约与几何仍有效后开放手动点按、长按、滑动；所有输入走现有任务串行通道。
4. 暂停超时或底层动作结果不确定时保持只读，不能通过另一路 root input 抢跑。
5. 选择继续 AI 时先结束手动输入、失效旧观察并重新观察，再恢复该任务。仅关闭手动窗口不会擅自恢复 AI。

已结束但仍保留页面的任务：没有可暂停的旧 run；按现有所有权规则取得该保留页面的手动控制权。同一 App 已被新任务占用时明确提示占用，不能借旧通知输入。继续指令由原会话建立后续运行，不复活已终结 run。

打开 App 到主屏：迁移原任务，继续用主屏窗口就绪、旧屏为空的确认释放；不复制上游固定等待 260ms 就释放的策略，不重复发送 Launcher Intent 或为适配强制重启 App。

### 4.5 等待用户与部分完成

在统一任务状态上增加清楚的产品结果说明：
- 等待用户决定与执行失败区分；
- 部分完成说明已完成项和剩余项，并使用既有继续指令入口；
- 已发布 run 结果仍由 Session 决定，不因预览窗口状态改变；
- 不根据一句“完成了”或模型停止流式输出推断用户目标完成，采用可验证结果/明确结构化状态；
- 本轮没有足够证据判断完整性时说明未确认，不伪造成功。

## 5. 第五轮：息屏与电源键兼容收尾

### 息屏按上游实际实现适配

上游没有本分支息屏即暂停处理，虚拟显示包含独立显示组、ALWAYS_UNLOCKED 与独立焦点标志。已查源码没有证明它为所有 ROM 解决了休眠网络限制；屏幕继续工作和模型联网必须分别验收。

- 适配范围是已授权的后台虚拟屏任务；前台主屏操作仍按主屏可用性处理，不因为支持后台息屏就继续盲点主屏。
- 复用现有 Runtime、前台服务和 VDrive；不另造常驻保活系统，不整套复制上游的公共显示/Hook 标志。
- 明确核对显示组/电源状态、输入是否被锁屏影响、网络请求与服务生命周期；不使用循环点亮主屏来伪装息屏执行。
- 保留用户原有暂停、取消及接管状态；亮屏不会自动重放旧动作或恢复用户主动暂停的任务。
- 网络不可用时展示真实等待/失败原因，重连不自动重放已经可能执行的设备动作。
- 在短时锁屏和较长空闲下分别验证模型联网、截图/输入、两个任务、停止与亮屏恢复。未过前保持现有暂停行为作为可回退基线。

### 电源键与 LSP

PowerHooks.kt 和 AssistantManager.kt 与上游 3.4.0 内容相同，不能重复覆盖后宣布修复。检查实际入口接线、包名/组件、模块配置及已有系统异常证据；区分上游新增虚拟屏权限 Hook 和电源键入口。不得为了试错扩大 system_server Hook 或主动触发软重启。

软重启、长任务后全局冷启动白屏仍是未确认解决的问题；常规小窗测试通过不代表这两个问题消失。
