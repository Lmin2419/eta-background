## 2. 实际完成的四项

### 统一任务状态

复用 AgentRuntimeSession.complete/cancel 的终态裁定，TaskPresentation 只投影已有结果、RuntimeRunRegistry 阶段及暂停原因，未建立第二套任务数据库。通知、运行界面与预览显示排队、准备、等待 GUI、暂停、停止中、收尾和实际终态；模型停止流式输出不提前完成卡片。归档提交后更新原卡片，旧 ShadowNotice 完成回调不能提前覆盖 Runtime 权威状态。

完成/取消竞争、提交中状态、取消排队任务、暂停状态均有回归。全量回归发现并修复取消已暂停前台任务后恢复控件消失的问题：全局前台权限暂停继续保留恢复入口，不将任务终态与权限状态混为一套。

### 通知作为三级预览入口

| 层级 | 实际行为 |
| --- | --- |
| 通知/流体云 | 仍使用 ProgressStyle；有后台目标 App 时请求小手机图标；位置和系统展开动画由 ROM 决定 |
| 点击通知 | 打开临时 App 小预览，只读，不暂停 AI，不移动原 App 到主屏 |
| 再点画面 | 展开为较大预览，可点“接管”进入手动操作；可再点缩回 |
| 关闭/隐藏 | 停止该窗口额外刷新并释放预览租约；不会取消任务或擅自恢复已暂停 AI |

Android Live Updates 不支持任意自定义通知画布。本候选按用户确认采用临时预览面板，不宣称实时画面嵌入原生流体云，不增加第二条卡片或常驻胶囊。通知内容点击与原“打开 App”action 使用不同 PendingIntent；三个完成入口“打开 ETA 会话 / 打开 App / 继续指令”和内联回复保留。

帧从现有 VDrive 的认证通道返回内存 JPEG，不调用会更新模型观察的 screen_shot，不持续写截图文件。小/大窗请求间隔约 800/350ms，长边最大 480/720px，编码上限 400KB，单窗口串行、缓存帧无变化跳过编码解码。隐藏停止消费者；已结束屏仅在查看时增加采集，关闭及空闲过期回收，活动任务原有采集保留。

窗口等比显示，横竖屏和黑边坐标有校验；旋转清理当前手势和旧几何。预览窗口不获取 IME 焦点，带 FLAG_SECURE，锁定时关闭。实际 ColorOS 焦点、主屏键盘及流体云布局仍待手机验证。

### 手动接管

控制绑定完整 runId 与包名，不使用全局当前屏或同包名兜底。每任务控制器暂停该任务，并等待已经准入的真实 transport 调用退出；引擎再检查 worker 排空及租约。等待或超时保持只读，不用第二条 root 输入路径抢跑。

取得控制后支持点按、长按、滑动和返回，旋转/几何变化拒绝旧坐标；超时或不确定结果不自动重放。另一任务继续执行。明确“让 AI 继续”时先释放手动控制再恢复任务，恢复代次让旧观察失效；单独关闭窗口不自动恢复。已结束任务只取得原保留页控制权，“结束接管”不复活旧 run；后续工作仍走通知内继续指令。

手动租约 10 秒无请求过期。旧通知不能控制后来同 App 的任务；页面回收时明确不可用，不能为了显示预览重启 App。“打开 App”继续使用原交还确认，不复制上游固定等待后直接释放屏幕的做法。

### 息屏继续后台执行

参考上游独立显示组、OWN_FOCUS、STEAL_TOP_FOCUS_DISABLED 与 ALWAYS_UNLOCKED，保留本分支主屏输入法/焦点隔离。Runtime 不再在 SCREEN_OFF 暂停全部 run：后台任务、后台开屏过渡及纯分析可继续；前台已操作任务暂停，锁屏时前台工具拒绝执行。

用户手动暂停和接管暂停不因解锁自动恢复；不自动重放网络失败前可能已执行的动作。没有新增主屏亮屏锁、常驻保活服务、网络白名单修改或系统 Hook。上游本身没有证明可绕过所有 ROM 的深度休眠网络限制，本候选也不作此承诺。
