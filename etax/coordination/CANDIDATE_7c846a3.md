## 修复与证据

1. 在原实现上新增两项回归均失败：预览直接暂停而 run 仍持 GUI 租约时，GUI 未记录该暂停，Runtime 只恢复 GUI 而遗漏任务控制器；手动拥有者仍存在时，GUI 暂停先被清除并虚报继续。现在分别恢复所属 GUI 状态和目标控制器；手动控制未释放则拒绝并说明原因。三次接管/交还循环与另一任务不受影响均有覆盖。
2. 预览根据真实控制器区分“AI 正在执行，预览只读”和“任务已暂停”。正在执行时只读是预期状态，不代表再次卡住。
3. 预览长边 640/960px，JPEG 质量 78；超过原 400KB 传输上限则回退质量 65，仍过大明确报错。不增加频率、持续写盘或 RPC 容量。
4. 通知图标改透明镂空轮廓及缓存位图；真实绘制后施加单色滤镜，验证不会变成白色实心矩形。ColorOS 染色仍为与截图一致的推断，须新包手机确认。没有把原生 ProgressStyle 换成自定义实时视频；实时可操作画面继续位于通知打开的小窗。
5. 全量回归发现现有通知打开会话测试失败，单独重现后查到实际 `Conversation content unavailable`，不是简单超时：加载返回缺失后跨线程再次判断，期间另一归档导入已创建聊天。将加载与缺失检查保持同次主线程执行；原整类测试、完整回归通过。未延长超时或跳过失败。
