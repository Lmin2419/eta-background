# 验证页面浏览器安装修订（2026-11-04）

基线：`3.3.5+etax.dafb1d9`，仓库提交 `8ba6703`。用户设备为 Debian 13、Root chroot；原界面仅显示“安装失败”，没有可判断的阶段、退出码或错误内容。因此本轮不能断言手机失败由网络、动态库或沙箱中的哪一项导致。

## 已确认与修改

- 原 `patchright install chromium` 同时下载 Chrome、FFmpeg 和未使用的 headless-shell。生产适配器使用 `channel="chromium"`，已核对其选择完整 Chrome。改为 `install --no-shell chromium`：ARM64 下载量从 327,499,082 字节降至 201,788,021 字节，减少约 126 MB；不删除用户已有的完整组件。
- 官方下载连接等待从默认 30 秒改为 60 秒；组件命令仍有 600 秒总上限，不无限延长或重试。
- 安装结果保留具体阶段、固定诊断码、退出码、是否超时和耗时。区分系统依赖安装、组件配置、浏览器下载/解压、完成标记写入。取消仍直接传播，不伪装成下载失败。
- 组件安装保留命令输出最后 64 KiB 用于识别末尾错误，不把原始输出、网址或凭据显示到 UI 或日志。其他安装调用保持原有前缀输出行为。
- 界面显示具体原因及处理建议，支持长按复制结构化诊断信息。未知原因保持未知，不能把所有失败都说成网络故障。
- 成功后的安装标记单独原子写入；依赖、下载或标记保存失败时不会报告本次安装完成。

## 下载与平台核对

固定 Patchright 1.64.4 支持 `debian13-arm64`。只读检查官方 ARM64 Node 与 Chromium 的 ELF 依赖，没有发现可以据此认定的缺库根因。没有为猜测追加系统包，也没有添加未经验证的二进制镜像或关闭 TLS/浏览器沙箱。

使用全新缓存运行真实 CLI `python -m patchright install --no-shell chromium`，实际联网下载并解压 ARM64 Chrome 与 FFmpeg，退出码 0，耗时 17.734 秒。缓存含 `chromium-1248`、`ffmpeg-1013`，没有 headless-shell。

具体命令、实际执行平台、目标架构、大小及限制见[结构化验证记录](validation/browser-install-arm64.json)。

该检查运行于云端 x86_64 Debian 13，通过 `PLAYWRIGHT_HOST_PLATFORM_OVERRIDE=debian13-arm64` 选择下载目标，**未执行 ARM64 Node 或浏览器**。平台覆盖产生的 fallback 提示、`DEPENDENCIES_VALIDATED` 文件都不能算手机运行验证；云端下载速度也不代表手机速度。

当前 ARM64 Chrome ZIP 为 199,750,508 字节，解压 418,439,600 字节；SHA-256：`910a12fff6170202195f72ef3d353801c7063d301ab80b1f51b77d791fda60ce`。官方下载地址最终重定向至 Google Storage，手机是否能够访问尚未验证。

## 手机验收

1. 覆盖安装候选包，保留现有 Debian 与已安装的网页增强组件。
2. 在「Linux 环境 → Debian → 可选工具」点击一次「验证页面浏览器」安装，安装期间留在此页。
3. 若失败，长按复制包含阶段、诊断码、退出码的提示。不要连续重复安装或重装整个 Debian。
4. 下载成功后再点「检查可用性」。下载完成、浏览器能启动、目标网页正文取得是三项不同结果，分别记录。

本轮不触发手机重启、不操作用户设备、不修改 Root 引擎或系统助手。
