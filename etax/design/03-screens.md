## S1 · 首页（对话）

### S1.1 顶栏
`≡`（打开侧栏）· 模型胶囊（居中）· 新对话 · 任务中心（有运行中任务时右上角 16dp 角标显示数量，底 `accent`）。
- 角色对话：模型胶囊左侧改为角色头像 24 + 角色名，点头像进角色详情（沿用现有 `CharacterTopBarIdentity`），模型胶囊收为仅图标。

### S1.2 空状态（新对话）
从上到下（内容整体在可视区上 1/3 处开始）：
1. 猫标记：48dp，使用 `ic_eta_mark`（由 `brand/pangxiaopang.svg` 生成），保持原图颜色；静止显示，进入时按 medium 淡入，减少动画时 ≤120ms。
2. 问候 `display`：按时间「早上好 / 下午好 / 晚上好」。
3. 副标题 `subhead textSecondary`：「说一句，我在前台或后台帮你做完。」
4. 建议卡 2 列网格（间距 12），最多 4 张：
   - 前两张来自**常用任务**（最近使用优先）：图标块 `tileCaramel` + 名称 `rowTitle` + 指令前 1 行 `footnote`；点按 = 直接执行（与常用任务页「运行」相同，开新会话）。
   - 其余为示例（没有常用任务时 4 张都是示例）：「在后台帮我点一杯咖啡」「总结今天的未读通知」「打开设置检查电池健康」「搜索并比较两款手机」。点按 = **填入输入框**，光标在末尾，不自动发送。
   - 卡片：底 `surface`，圆角 `radiusMd`，内边距 14，高 88；按压缩放 0.98。
5. 首次安装且「系统就绪」有缺项时，建议卡上方显示一条 `attention` 提示卡：「还差 2 项设置才能在后台操作 App」+「去完成」→ 设置页就绪卡。

### S1.3 对话中
- 消息列：最大宽度 720 居中；消息间距：同一轮内 12，轮与轮之间 24。
- 用户消息 C20；助手消息 C21；工作过程 C22 放在该轮助手正文之前。
- 输入栏 C24 固定在底部；其上依次是排队条 C25、实时任务条 C23；回到底部按钮 C26。
- 首次打开长会话：直接定位到底部，无滚动动画；向上滚到顶部自动加载更早消息（沿用现有分页），加载时顶部显示骨架行。
- 流式中：底部跟随（沿用现有 `resolveBottomFollowDecision`），用户手动上滑后停止跟随并出现回到底部按钮。

### S1.4 对话设置面板（点模型胶囊）
EtaSheet，标题「对话设置」：
1. **模型**：按服务商分组的列表（服务商小标题 `caption`），每行：模型名 `rowTitle` + 能力小标签（视觉 / 思考 / 工具，`caption` 灰底 Chip）+ 选中对勾 `accent`。顶部搜索框（模型 > 8 个时出现）。底部「管理模型服务商 ›」→ 模型服务商页。
2. **本对话**（分组列表）：自动朗读（开关，仅配置了语音合成时显示）、压缩上下文（按钮行，显示当前 token 占用，不可用时禁用并说明）、导出对话（Markdown）。
- 选模型后面板自动关闭，Toast「已切换到 xxx」。

### S1.5 附件面板（点 `+`）
EtaSheet 菜单型，4 个大图标格（2×2 或横排 4 个）：图片、文件、文件夹、设备路径。下方可选「最近图片」横向缩略图（若读取相册已授权；否则不显示，不主动申请权限）。

### S1.6 消息长按
- 用户消息：复制 / 编辑 / 删除。
- 助手消息：复制 / 朗读 / 重新生成 / 删除。
- 删除需确认（EtaDialog，Destructive）。

### S1.7 实时任务条交互
见 C23。补充：
- 任务完成：条变为 `success` 状态 3s「已完成 · 用时 2分13秒」，然后收起（`medium`）；结果正文正常进入对话。
- 任务失败/停止：条变 `danger`，保留到用户点 ×。
- 用户在预览窗接管后返回 App：条显示「你在操作」，按钮变「交还 AI」。

### S1.8 横屏与平板（≥840dp）
侧栏常驻左侧（宽 320，`surface`，右侧 1px `outline`），对话区居中最大 720；任务中心在对话区右侧以 360 宽面板打开（不跳页）。

### S1.9 底部输入区与消息区的衔接（阶段 5 真机反馈后补充）

**问题**：消息区透出外层 Scaffold 的默认底色 `surface`（浅色白 / 深色 `#16171C`），而输入栏外层 Column 和首页顶栏刷的是 `canvas`（浅色 `#F4F5F8` / 深色 `#0D0E12`）。输入卡片坐在一条比消息区深一档的实心色带上，色带上沿是一条硬直线，浅色模式下尤其明显。阶段 3 去掉了原来输入栏上方的渐隐，这条线也就没有过渡了。

**规则**：
1. 首页整页只有一个底色：`canvas`。壳层 Scaffold（首页路由）`containerColor = canvas`，聊天 Scaffold 保持透明，顶栏、消息区、输入区下方都是 `canvas`。不允许在消息区和输入区之间出现任何一条色带或直线。
2. 输入区外层（包含实时任务条、排队条和输入卡片）**不刷实心色块**，改为一道纵向渐变：最上方 24dp 从 `canvas` 0% 过渡到 `canvas` 100%，以下到导航栏底部为实心 `canvas`。渐变区画在最上面那个元素（实时任务条 / 排队条 / 输入卡片）的上方，不压在卡片上沿。效果：消息滚到输入区下面时是渐渐淡出，而不是被一条边切断。
3. 消息列表 `contentPadding.bottom` 继续等于整个输入区高度（含 24dp 渐变），最后一条消息停在渐变上方，不被遮挡。
4. 输入卡片：浅色 = 白底 `surfaceRaised` + `e2` 阴影；深色 = `surfaceRaised` `#1E2027` + 1px `outline`，**不画阴影**。卡片四周（左右 12、下 8）露出的都是同一个 `canvas`。
5. 无消息（空状态）时不需要渐变，但同样不能有色带。
6. 键盘弹出、实时任务条出现/消失、排队条展开时，渐变始终跟随最上方元素，不闪、不跳。

**验收**：浅色、深色、200% 字号各截一张有长消息的首页图（消息滚到输入区下方），肉眼看不到横向色带或硬边；消息在输入区上方 24dp 内逐渐淡出。

## S2 · 会话侧栏

保持现有「推移」式侧栏（`ConversationSidePaneScaffold`，主内容随之右移并缩小圆角），宽度 min(84%, 360)，底 `surface`。
1. **顶部**（距状态栏 8）：搜索框 C9 + 右侧「新对话」图标按钮。
2. **工作区快捷入口**：一行 4 个，等宽，每个 = 图标块 40（分类色）+ `caption` 名称：任务（`tileCaramel`，有运行时右上角角标）、角色（`tilePink`）、终端（`tileSlate`）、浏览器（`tileTeal`）。Kimi Code 以第 5 个出现（若已配置），横向可滑。
3. **会话列表**：分组小标题（置顶 / 今天 / 昨天 / 7 天内 / 更早，`caption textTertiary`）。
   - 行高 48，左右内边距 12，圆角 `radiusMd`；标题 `rowTitle` 15sp 单行；右侧相对时间 `caption textTertiary`。
   - 当前会话：底 `accentSoft`，标题 `onAccentSoft`。
   - 有任务在跑的会话：标题左侧 `StatusRing 12`（运行中/需要你）。
   - 长按：触感 + EtaSheet「重命名 / 导出 / 删除」（删除二次确认）。
   - 搜索中：列表实时过滤，匹配字高亮 `accent`；无结果显示 C14 空状态。
4. **底部固定栏**（顶 1px `outline`，高 64）：左「设置」（图标 + 文字；系统就绪有缺项时图标右上角 `attention` 圆点）；右「权限」（图标 + 「1 项待处理」或「全部正常」，`subhead`）。

### S2.5 会话批量管理：多选、批量删除、归档（阶段 5 真机反馈后补充）

**进入与退出**
- 在会话列表里**长按任意一条** → 触感反馈，进入多选模式，这条已选中。（原来长按弹出的「重命名 / 导出 / 删除」面板取消，这些操作移到多选操作栏里。）
- 多选模式下，点按任意行 = 切换选中，不打开会话。
- 退出：点顶部「取消」、系统返回手势、或选中数降为 0（自动退出）。

**多选模式的界面**（替换侧栏顶部和底部，列表本身不动）
- 顶部（替换搜索框那一行，高 56）：左 `✕` 图标按钮（取消）+「已选 3 个」(`headline`)；右侧文字按钮「全选」/「取消全选」。全选只选当前列表里可见的（受搜索过滤影响）。
- 每行左侧出现 20dp 圆形勾选框（未选：1.5dp `outlineStrong` 描边；选中：`accent` 实心 + 白色对勾），行标题右移，选中行底色 `accentSoft`。有任务在跑的会话，状态环移到行尾。
- 底部（替换「设置 / 权限」固定栏，高 64，顶 1px `outline`）三个按钮等分：**归档**（Tonal）、**删除**（Destructive）、**更多**（图标 `MoreHoriz` → EtaSheet：重命名、导出；仅选中 1 个时可用，否则灰掉并在面板里写「仅单选时可用」）。
- 行的勾选和操作栏切换动画 `short`；多选模式下工作区快捷入口行隐藏（`medium` 收起）。

**批量删除**
- 点「删除」→ EtaDialog：标题「删除 3 个对话？」，正文「对话记录会被永久删除，无法恢复。」；若选中项里有正在执行任务的，正文再加一行「其中 1 个正在执行任务，会先停止任务再删除。」按钮：取消（Ghost）/ 删除（Destructive）。
- 删除沿用现有 `deleteConversation` 的规则（运行中的先停止再删），但新增批量入口 `deleteConversations(ids)`：**一次状态更新、一次持久化**，不要循环调用单条删除导致多次重算与多次写库。
- 删除当前打开的会话时，和现在一样切到下一条。完成后 Toast「已删除 3 个对话」。

**归档**
- 点「归档」→ 不弹确认，直接归档，Toast「已归档 3 个对话」+ 操作「撤销」（3 秒内点撤销恢复）。
- 有任务在跑的会话**不归档**，跳过并在 Toast 里说明：「已归档 2 个，1 个正在执行任务未归档」。
- 归档后的会话不出现在主列表；列表最底部固定一行「已归档 · 12」（`subhead textSecondary`，右侧 `ChevronRight`；数量为 0 时不显示）→ 进入侧栏内的「已归档」子页：顶部「‹ 已归档」，下面同样的会话行，同样可长按多选，操作栏为 **取消归档**（Tonal）/ **删除**（Destructive）/ 更多。
- 搜索时结果包含已归档会话，行尾加 `caption` 灰底小标签「已归档」。
- 从搜索、任务中心、通知进入已归档会话：正常打开。在已归档会话里**发出新消息**（含通知栏继续指令）→ 自动取消归档，回到主列表。
- 当前打开的会话被归档：和删除一样切到下一条。

**数据**（这一项需要非界面改动，属于允许范围）
- Room 迁移 23 → 24：`conversations` 表新增可空列 `archived_at INTEGER`（null = 未归档）。`ConversationEntity` / `ConversationMetadata` / `ConversationIndexRow` 同步加字段。必须带迁移测试（旧库数据完整、新列为 null）。
- 数据备份与恢复带上 `archived_at`；旧备份没有该字段时按未归档恢复。备份格式版本按仓库现有约定递增。
- 不新增「置顶」功能（`isPinned` 目前没有数据来源，保持现状）。

## S3 · 任务中心（新增路由 `AppRoute.Tasks`）

大标题顶栏「任务」，下方分段控件 C10：**进行中 · 已完成 · 常用**。默认：有进行中任务时选「进行中」，否则「常用」。

### S3.1 进行中
每个运行中/暂停/需要你的任务一张卡（EtaCard，内边距 16）：
```
[应用图标 24] 美团 · 点外卖                [状态 Chip]
┌────────┐  正在点击“提交订单”
│ 实时   │  第 8 步 · 1分12秒
│ 缩略图 │
│ 72×156 │  [查看]  [暂停]  [停止]
└────────┘
```
- 缩略图：圆角 `radiusSm`，1px `outline`；仅当本页可见且卡片在屏幕内时，每 2 秒取一帧（复用 `preview_frame` RPC，`edge` = 320）；离开页面立即停止。无画面时显示应用图标居中的占位。
- 「查看」(Tonal) → 任务预览窗；「暂停/继续」(Secondary)；「停止」(Destructive Small) → 确认对话框。
- 前台任务（不在虚拟屏）不显示缩略图，卡片只有文字。
- 「需要你」的卡片排在最前，用状态 Chip + 卡片 1.5dp `attention` 描边标出（不用左侧色条）。
- 空：C14「没有正在执行的任务」+ Tonal「从常用任务开始」→ 切到「常用」页签。

### S3.2 已完成
最近 20 条（来自通知卡片 / 运行归档，按结束时间倒序）：行 = StatusRing 16 + 标题 `rowTitle` + 副行「美团 · 14:32 · 用时 2分13秒」`footnote textTertiary` + 尾部「打开 App」Small Secondary（目标应用可打开时）。点行 → 打开对应会话。

### S3.3 常用
现有 `CommonTasksScreen` 的内容换装：
- 每条一张卡：名称 `headline`、指令前两行 `subhead textSecondary`、底部「运行」Tonal Small + 右侧「…」（编辑 / 复制 / 添加到桌面 / 删除）。
- 右下角扩展悬浮按钮「新建」（Primary，高 52，圆角 full，`e2`），列表滚动时收为圆形。
- 编辑页：名称输入、指令多行输入（`body`），底部 Primary「保存」。

数据：进行中 = `AgentExecutionService` 卡片快照（同进程，新增 `StateFlow`）+ `TaskPreviewRegistry`；已完成 = 同一快照中 `completed` 的卡片 + 归档；常用 = 现有 `CommonTasksStore`。

## S10 · 细节修正（2026110614 真机反馈）

用户真机反馈两处，设计侧又按同类问题把全部渲染排查了一遍。本节只改尺寸、对齐、行数和文案，不改业务逻辑、状态机、窗口几何和动画。每一条都附**可测的验收标准**，用 Robolectric 原生渲染断言，不只靠截图目测。

### S10.1 预览窗头部应用名被压成「…」（用户反馈）
- 现象：小窗宽只有屏宽 × 0.62（393dp 手机约 244dp）。头部一行要放 24 图标 + 状态 Chip + 两个 48 按钮，应用名的宽度被算成 0，只剩「…」；状态 Chip 自己也被截成「已暂停 · 你…」。原 S5 布局图没算宽度，这是设计侧的问题。
- 规则：见 S5 新布局。标题区两行，应用名独占图标和按钮之间的全部宽度；接管中状态文字缩短为「你在操作」（英文 "You're in control"，繁体「你在操作」）。接管中已经有 2dp `accent` 画面描边和「交还 AI」按钮，不需要再写「已暂停」。
- 提示行固定两行高，长步骤（如「正在点击“提交订单”，等待页面加载完成」）在小窗能看全，画面区高度不随文字变化。
- 验收：
  - 244dp 宽、字号 100%：「中国移动云盘」6 个字完整显示，不省略（`TextLayoutResult.isLineEllipsized(0) == false`）；「Google Chrome」完整或只截最后 1–2 个字母。
  - 223dp 宽（360dp 手机）：6 字名称至少显示 4 字再省略，任何情况下都不能只剩「…」。
  - 字号 200%：放大、关闭按钮仍是 48dp，名称至少显示 2 字。
  - 状态文字 5 种状态在 244dp 下均完整显示。
  - 浅色、深色都要截图。TalkBack 朗读内容不变（名称、状态、步骤）。

### S10.2 对话任务条的状态圈压住应用图标（用户反馈）
- 现象：`StatusRing 12` 直接画在 28 图标的右下角，重叠 8×8dp，中间镂空能透出图标，看着像图标被划了一道。
- 规则：见 C23 状态徽标（16dp 圆垫抠图 + 圆心在图标右下角外侧）。所有「图标 + 角标」的地方都按这个规则，目前只有任务条这一处，多任务叠放头像同步加圆垫描边。
- 验收：用一张不透明正方形图标渲染，徽标覆盖的图标像素 ≤ 4×4dp；换成圆形图标，覆盖为 0。运行中流光动画、减少动画时静止不变。

### S10.3 首页建议卡副标题只显示 7–8 个字
- 现象：两列卡片的副标题单行，中文只剩「在后台帮我点一杯…」「总结今天的未读通…」，看不出要做什么。
- 规则：副标题最多 2 行；同一行的两张卡等高（按较高的一张对齐）；标题仍最多 2 行。
- 验收：393dp 宽、100% 字号下，四张预设卡的中文副标题全部完整显示。

### S10.4 常用任务卡的「⋯」和「立即运行」没对齐
- 现象：「⋯」图标按钮比「立即运行」低约 8dp（行没有设置垂直居中）。
- 规则：这一行垂直居中。
- 验收：两者中心 Y 相差 ≤ 1dp。列表到底时最后一张卡的「⋯」不被新建按钮挡住（现有 96dp 底部留白保持）。

### S10.5 权限就绪卡标签在单词中间断行（英文）
- 现象：英文下「Accessibilit / y」「Notification / s」。中文没有这个问题，但 App 支持英文。
- 规则：标签不允许在单词中间断行。英文用短标签（Root、A11y、Overlay、Alerts、Engine），完整名称放进读屏描述；中文、繁体标签不变。

### S10.10 状态栏胶囊短文字不再硬截断
- 现象：`setShortCriticalText` 用 `take(7)` 截字符串，会出现「已暂停，等待你」「已完成 · 回复」这类半句话。
- 规则：给每种状态一个专用短标签（≤ 4 个字），不再用 `take(N)`。

  | 状态 | 短标签 |
  | --- | --- |
  | 排队 | 排队中 |
  | 执行 / 观察 / 打开应用 | 执行中 |
  | 等模型 | 思考中 |
  | 生成回答 | 回答中 |
  | 暂停 | 已暂停 |
  | 你在接管 | 你在操作 |
  | 需要你 | 需要你 |
  | 收尾 | 收尾中 |
  | 完成 | 已完成 |
  | 停止 | 已停止 |
  | 失败 | 未完成 |

  繁体、英文同义，英文 ≤ 10 个字符。
- 验收：遍历所有 `AgentOverlayStatus` 和三种完成态，短文字都来自上表，长度符合限制。

## S11 · 息屏不暂停（对齐上游 v3.3.5，用户要求）

用户原话：「息屏不要暂停……直接按上游那边的操作就行了，上游息屏的时候还能完成一些任务」。

**现状对比**（已对照上游 `v3.3.5` 源码）：

| | 上游 v3.3.5 | 本分支现在 |
| --- | --- | --- |
| 息屏广播 | 不监听，任务照常跑 | `AgentRuntimeService.screenReceiver` 收到 `ACTION_SCREEN_OFF`，会暂停主屏上碰过前台工具的任务（`pausedForScreenOff`）；亮屏后不自动恢复，必须解锁后手动点「继续」 |
| 后台虚拟屏任务 | 无此功能 | 不暂停 |
| GUI 任务运行时保持亮屏 | 有（胶囊 `keepScreenOn`） | 有，同上游 |
| 锁屏时操作主屏 | 无检查 | `beforeToolExecution` 拒绝，返回 `SCREEN_LOCKED`，任务本身不停 |
| 唤醒锁 | 无 | 无 |

**新规则**：
1. 删除息屏暂停：`ACTION_SCREEN_OFF` 不再暂停任何任务，保留现在的隐藏流光和胶囊、刷新状态的逻辑。删除不再使用的 `pausedForScreenOff`、`ScreenOffPaused` 和「已息屏暂停，解锁后继续」文案。
2. 保留锁屏保护：屏幕关闭或锁屏时，主屏点击、输入类工具仍返回 `SCREEN_LOCKED`。原因：这不会暂停任务，只是不让 AI 在锁屏界面上乱点（可能误触相机、紧急呼叫）；模型收到错误后，可以继续做不需要主屏的步骤，或改用后台虚拟屏。上游在息屏时这类操作本来也不会成功。
3. 用户手动暂停、接管的任务仍然不会自动恢复。
4. 亮屏后，如果任务还在跑，流光和胶囊按当前状态重新出现；任务条、通知显示真实状态，不能停在「已暂停」。
5. 不新增唤醒锁、常驻保活或亮屏锁，和上游一致。系统省电导致的断网不在承诺范围内。

**验收**：
- 改写 `AgentRuntimeScreenOnTest.physicalScreenOffPausesRunAndScreenOnRequiresManualResume`：息屏后任务不暂停；已手动暂停的任务息屏、亮屏后仍暂停；锁屏时主屏 GUI 工具仍被拒绝。
- 真机三项：
  - **纯思考 / 搜索任务**：发出后立刻按电源键，等一会儿再亮屏，任务已完成，或者还在继续，不是「已暂停」。
  - **主屏操作任务**：执行中按电源键，任务不暂停；锁屏期间没有任何误触；解锁后能看到 AI 改用后台屏，或说明了哪一步没法在锁屏时做。
  - **后台虚拟屏任务**：息屏后继续，行为不变。
