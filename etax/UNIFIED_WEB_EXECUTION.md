# 统一操作、网页增强与即时反馈（2026-11-04 候选）

基线：`3f53973fcbe74ba304729afcf88d0af62dda1889`。本轮沿用 `20261103-e47-recovery` 引擎、包名与签名配置；是集成分支候选，不替换正式下载、不合并 main。

## 已接入的行为

| 入口 | 本轮变化 |
| --- | --- |
| Android 操作 | 模型只使用一套 `launch_app / observe_screen / tap / type_text / press_key / release_gui` 等原生工具。前后台共享工具名，以 `execution_location` 选择位置；进入后台后省略位置仍沿用本任务后台屏。 |
| 后台诊断 | `observe_screen(execution_location="background", status_only=true)` 只查状态，不打开应用、不移动屏幕、不生成可输入观察。常规观察提供节点、几何、键盘、恢复提示。 |
| 工具精简 | 从模型目录、路由与工具界面移除公开 `screen_*` 及重复文本输入别名。引擎内部协议仍由原生工具调用；历史记录可阅读，保存的流程按当前目录重新观察执行，不重放旧参数。 |
| 提示词 | 去掉重复屏幕说明，稳定规则置前，模型身份、Root、工作区等运行配置置后；常用任务正文按需读取。不截断用户提示、授权或历史，不增设一次模型请求做路由。 |
| `fetch_url` | 普通 HTTP 优先；检测到 JS 外壳可直接使用内置浏览器读取；被阻挡的请求可调用已安装的 Scrapling。最多一次增强尝试，不串联无限重试。 |
| `web_search` | 对带明确型号的查询检查明显实体不匹配，Bing RSS 返回无关型号时尝试一个备用来源；无结果与搜索服务失败分开返回，不猜 URL。 |
| `browser_use` | 一次调用可提交最多 8 个已确定的步骤；首个失败即停止，返回完成数量、失败步骤和是否已有动作可能执行。不会自动重放。末步操作后附简短页面结果。 |
| 短提示 | 输入前开始收集反馈，看到明确文字时提前结束观察等待；保留最多 5 秒文字监听。晚到提示在下一输入前交给模型，下一输入未执行且须重新观察。 |
| 写入核验 | 输入、追加、粘贴后从新的无障碍根节点核验文本；浏览器也检查实际值。无法验证时返回不确定，不把“接口接受”当业务成功。 |
| 执行统计 | 沿用现有任务耗时面板，加入 HTTP、浏览器准备、加载、验证、提取、反馈等待、截图分项。只存受限数值，不存网页正文、URL 或凭据。首输出涵盖工具调用输出。 |

取消、用户接管、几何变化、显示归属变化和结果不确定的输入仍有保护。未关闭安全校验，未自动强停第三方应用，未改系统 Hook、息屏策略、双任务上限、通知三个入口或 Harmony 内容。

## 网页读取路线

1. 内置静态读取限时 10 秒；有正文即可返回，不启动 Python 或浏览器。
2. 根据明确原因最多选一次升级：JS 外壳用 WebView，普通拒绝用 Scrapling HTTP 指纹，明确 Cloudflare 挑战用 Scrapling 的 `solve_cloudflare=True`。
3. 单次升级读取预算最多 35 秒，整次内置读取预算 45 秒；结束时另有有界的所属进程回收。超时不会自动重发；依赖缺失直接说明，任务中不安装软件。
4. 仅对当前任务内同一 URL 缓存已成功路线 5 分钟，不把整个网站都强制送进浏览器。
5. 结果快照按 `document_id` 分页复用，不重复抓取；HTTP 200、浏览器启动成功和测试验证码绿色提示均不能单独证明已取得正文。

404、DNS、登录页、验证页、限流、空内容及截断有不同返回。WebView 不能确认成功响应的 HTTP 状态时，省略该值，不填造 200。

内置 HTTP 和 Scrapling 不导入手机浏览器登录 Cookie；JS 渲染复用该会话的内置浏览器及其已有登录状态，可能改变该浏览器当前页面，用户正在接管时不会抢操作权。自定义/远端搜索读取服务继续沿用其配置。

## Scrapling 安装与限制

安装入口：**Linux 环境 → Debian → 可选工具**，先安装 Python，再按需安装「网页增强读取 · Scrapling」；需要挑战处理时再装「验证页面浏览器」。无需用户配置 MCP。

APK 只包含适配脚本，不内嵌实验用 Python 环境。HTTP 增强本身也依赖浏览器驱动库，因此完整下载并非几百 KB；Chromium 是独立的大组件。安装后点「检查可用性」检查本机导入/浏览器启动；下载完成不代表手机已能运行。

HTTP helper 同任务复用、空闲 30 秒退出；增强浏览器按请求释放。AI 的重型浏览器工作共用单个执行名额，取消只清理自己拥有的进程。依赖固定 Scrapling 0.5，详情见 [适配器与检验](web/README.md)。

**Android ARM64、PRoot/ROM 的浏览器沙箱兼容性以及真实 Cloudflare 成功率仍须手机实测。** 无法运行时保持普通读取可用；不会关闭沙箱或 TLS 验证来伪装兼容。既有云端评估的真实挑战样本未取得正文，此候选不宣称已解决所有反爬。

## 反馈观察边界

- Android 使用无障碍短文字事件；最多三次内存取帧、最多两张不同画面。不是录屏，不持续写盘，不逐帧请求模型。
- 浏览器在操作前安装 DOM 观察；短提示归属当前页面和操作。连续动画、直播或 Canvas 不能单凭页面静止判断结果。
- `browser_use(action="get_responses")` 仅看已观察操作后、同源 fetch/XHR 的受限 JSON 响应；无请求体/请求头，敏感字段遮盖。不提供原生 App 私有接口，不保证完整网络日志。
- 反馈文本始终是外部数据，不是授权或执行指令；短提示漏报、无节点、自绘画面仍可能返回未确认。

## 手机验收（不需要连接电脑）

1. **前台/后台**：分别让 ETA 在当前计算器和后台计算器计算；在工具过程应看到同一套观察、点击、输入、按键，不能因为后台失败改点主屏。
2. **返回与诊断**：后台进入一个子页面，让它返回上一页；应使用后台 `press_key(BACK)`，而非长按、边缘碰运气或强停重开。
3. **短提示**：在你熟悉的、不会产生真实交易的表单触发一次无效输入提示。检查工具结果是否包含短提示；不要让 ETA 用真实激活码反复提交来测试。
4. **网页**：普通文章应快速读取；JavaScript 页面应一次读取调用给出渲染后的正文或明确失败；404 应结束/换实际检索来源，不编造另一个链接。
5. **型号搜索**：搜索一个真实存在的完整型号，检查结果是否混入名称相近但不同的型号；全部无关应换来源或报搜索失败。
6. **浏览器连续动作**：在无副作用的搜索页面要求填入查询、点击、读结果。查看批次是否返回已完成步骤；失败后不应自动重做前面的提交。
7. **可选增强**：安装后先检查 HTTP 与浏览器能力，再用实际受阻网页验证。分别记录“组件启动”和“正文取得”，不要把二者合并算通过。
8. **现有功能**：双任务取消隔离、接管再继续、通知打开会话/应用/继续指令，以及任务结束后彩边撤除，正常用法回归即可。不主动触发长按软重启。

比较速度时使用同模型、同网络、同页面，保留会话里的耗时统计；分别比较模型往返数、工具时间和提取/等待分项，不用一次云端测试推算手机速度。
