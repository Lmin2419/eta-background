## 与 Eta 的差异、待用户确认

1. 按已确认决定使用原生手势、弹窗、动画和圆角；队列展开使用原 180ms。最终视觉/按钮触摸范围等检查点 ② 截图后判断是否自绘。
2. 保留 0.9 轮次存储；L4 的消息投影在桥接处映射为原有稳定 turn ID，流式、结算与重启保持同一消息身份。仅活动运行有单调时钟，未给旧历史虚构思考耗时。
3. 与 Eta 一样，待发送队列不写进会话存档；关闭进程不会自动续发队列。现有草稿持久化保留。继续使用 M0 的进入后台停止策略，后台长期运行不在本任务开启。
4. 既有 8000 字输入限制继续保留。撤回合并超限时提示并保留两端内容，不截掉排队消息。
5. 修订沿用原普通聊天语义，删除后续轮次；没有恢复角色多候选、附件或压缩运行。失败时不能访问网络，也不能丢失旧历史。运行结果未保存时不会继续消费队列。

真机检查点 ②（全部**待测**）：

1. 生成中发送两条短消息，看到数量与预览，展开显示序号；按序只执行一次。
2. 点队列文字撤回并保留原草稿；移除项不发送。闪电/长按发送优先执行；手动停止后队列保留，不自动继续。
3. 长按早期用户消息 → 编辑：后续暂隐藏，输入原文，有替换提醒；取消恢复原草稿；发送后只有前缀和新轮次，模型不见被截断的回复。
4. 助手最后一轮重新生成直接执行，早期轮次弹确认；取消不变；删除第一轮移除会话。生成中不能修订。
5. 流式过程中停止、切会话、切后台、杀进程重开：已收到内容保留，不自动重放；两个会话的队列/草稿/模型不混用。
6. 与 Eta 对照队列折叠/展开、长按菜单、修订提示、确认弹窗截图及手势录屏；思考结束显示真实秒数。未生成 HAP，以上结果均待用户 DevEco 与真机确认。
