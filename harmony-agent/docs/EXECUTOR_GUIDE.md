# 执行手册

本手册写给在本仓库执行任务的编码代理（当前是 dsh）。三份文件的关系：

- [AGENTS.md](../AGENTS.md)：规则，违反即视为缺陷；
- [ROADMAP.md](ROADMAP.md)：任务卡和本轮队列；
- 本手册：具体怎么做、怎么自测、怎么交付。

目标只有一个：**交给用户之前，问题已经在预览器里发现并修好**。用户只在“真机检查点”测试，不需要每个 PR 都上手机。

## 1. 分工与流程

| 谁 | 做什么 |
| --- | --- |
| Claude | 写任务卡；验收 PR；处理工具链和难点（例如原生库编译） |
| dsh | 按任务卡改代码、写测试；在预览器里自测；开 PR；按验收意见修改 |
| 用户 | 合并验收通过的 PR；在真机检查点用 DevEco 编译安装并测试 |

```
任务卡 → dsh 实现 → npm run verify 全部通过 → 开 PR → Claude 验收 ─通过→ 用户合并
                                                        └退回→ dsh 按编号逐条修改
```

真机测试只在任务卡写明的“真机检查点”进行，由 dsh 把步骤汇总成一份清单（见第 6 节）。

## 2. 开始一个任务

1. **读完整张任务卡**，确认四件事：
   - 目标；
   - 允许修改的文件；
   - 不许做的事；
   - 验收条件。
2. **拉分支**：从任务卡写明的 base 拉 `harmony/<编号>-<短名>`。没写 base 时：
   - 整条 PR 链合并进 `main` 之后，用 `main`；
   - 合并之前，用 `harmony/ui-preview-tests`。
   - 互不依赖的任务都从 base 直接拉，**不要叠在自己上一个任务的分支上**，除非任务卡要求。
3. **先跑验收场景**：任务卡给了 `tests/ui/pending/*.json` 时，先运行它，确认现在是失败的，并记下失败信息：

   ```bash
   npm run test:ui -- tests/ui/pending/05-reply-visible.json
   ```

4. **有疑问时**：
   - 小问题，选最接近 Eta 源码的做法，写进 PR 的“待确认”；
   - 会影响后续任务的问题，停下来，在 PR 里写清楚选项，等决定。

## 3. 交付前自检（硬性要求）

### 3.1 一条命令

```bash
export OHOS_SDK_ETS=~/.cache/ohos-sdk-26/ets
npm run verify
```

它依次运行 `check`、`test`、`check:ets`、`check:res`、`test:ui`。每项的日志在 `dist/verify/*.log`。汇总在 `dist/verify/summary.md`，**原样贴进 PR**。任何一项失败，都不能把 PR 标为可审查。

运行前先提交代码。工作区有未提交的改动时，摘要里会注明，需要提交后重跑。

### 3.2 本地跑不了预览器时

例如没有 sudo，或者下载不了 SDK：

1. 运行 `npm run verify -- --no-ui`；
2. 推送分支；
3. 等 PR 上的 CI 任务 `Harmony / UI preview tests` 完成，在运行页面的 Summary 里看每个场景的结果（失败时写明哪一步、什么错误）；
4. 截图和日志在 CI 附件 `ui-report` 里。

CI 不绿，不能标为可审查。

### 3.3 改了界面或交互的 PR 还要做到

- **场景**：新增或更新 `tests/ui/` 场景。场景要断言**结果**，不能只断言“页面打开了”。例如：
  - 点“删除”后，消息不见了（`expectMissing`）；
  - 切换开关后，状态文字变了。
- **截图**：在 PR 中列出关键截图的文件名，例如 `ui-report/07-appearance/dark.jpg`，Claude 会看图验收。
- **没有新的应用错误**：`npm run test:ui` 每一步都会检查预览器日志，这一条自动满足。

### 3.4 自查清单（复制到 PR 中逐项勾选）

```
- [ ] 只改了任务卡允许的文件；没有顺手重构、改格式或升级依赖
- [ ] npm run verify 全部通过，摘要已贴
- [ ] 界面改动：已加 / 改场景，场景断言了结果；已列出截图
- [ ] 没有删除、跳过或放宽任何测试和检查；没有加 @ts-ignore、any
- [ ] 移植文件有来源注释（Ported from … @ 3b1794d）
- [ ] 颜色、尺寸、文案、图标走资源和 tokens
- [ ] 没有新权限；如有，已单独列出并说明原因
- [ ] 版本号已升（app.json5 两处 + package.json）
- [ ] PROJECT_STATUS.md 已更新；没有写“真机通过”
- [ ] 没有提交密钥、证书、签名配置、dist/、oh_modules/、SDK
```

## 4. 用预览器排查问题

### 4.1 用户报告了问题

不要直接改代码再请用户重测。先在预览器里复现：

1. **写复现场景**：新建 `tests/ui/pending/bug-<短名>.json`，按用户描述的步骤操作，最后一步断言**正确的结果**。
2. **确认它失败**，而且失败原因和用户描述一致。
3. **修复**，直到场景通过。
4. **把场景移到 `tests/ui/`**，以后它就是回归测试。
5. **复现不了时**（例如存储、网络、签名、性能、真实系统弹窗），在 PR 里写明“预览器无法复现，原因是……”，再给用户**最少**的真机步骤。

### 4.2 不知道页面上有什么

- 在场景里加一步 `{"dump": "名字"}`：打印当前所有可见元素，同时保存截图。每行的格式是：

  ```
  类型 | id | 文字 | a11y=无障碍文字 | placeholder=占位文字 | 是否禁用 | 位置
  ```

  例如：

  ```
  Button |  |  | a11y=会话历史 |  |  | 32,12 80x80
  TextArea | id=eta-composer |  |  | placeholder=交给 随身助手 去完成 |  | 53,1647 1158x80
  MenuItem |  | '编辑' |  |  |  | 856,315 240x96
  ```

- **步骤失败时会自动打印**：前 60 个可见元素和新出现的应用错误。完整列表在 `dist/ui-report/<场景>/failed-step-NN-elements.txt`，截图是同名的 `.jpg`。
- **预览器日志**：`dist/ui-report/<场景>/previewer.log`。搜 `FIX THIS APPLICATION ERROR`、`TypeError`、`ReferenceError`、`JsEngine Crash`。

### 4.3 选择器怎么写

- 按钮优先用 `a11y`（无障碍文字）。它同时是真机无障碍需要的，缺了就补 `.accessibilityText($r(...))`。
- 文字不唯一时，给组件加 `.id('eta-xxx')`，场景里用 `{"id": "eta-xxx"}`。加 id 不影响界面。
- 不要用坐标点击。唯一的例外是系统对话框，见 4.4 的 `tapAt`。

### 4.4 步骤速查

| 步骤 | 写法 | 说明 |
| --- | --- | --- |
| 等待出现 | `{"waitFor": {选择器}, "timeout": 15}` | 默认等 8 秒 |
| 应当可见 | `{"expect": {选择器}}` | 同上 |
| 应当消失 | `{"expectMissing": {选择器}}` | |
| 点击 | `{"tap": {选择器}}` | 点击后界面没有变化判为失败；预期不变时加 `"expectChange": false` |
| 长按 | `{"longPress": {选择器}, "hold": 1.0}` | `"offset": [-50, 0]` 从中心偏移若干像素，例如按在气泡边缘而不是文字上 |
| 滑动 | `{"swipe": {"direction": "right"}}` | 方向为 `up`、`down`、`left`、`right`。`"on": {选择器}` 在某个元素上滑；`"distance": 0.6` 是滑动距离占比 |
| 返回 | `{"back": true}` | 系统返回键 |
| 点系统对话框 | `{"tapAt": [0.65, 0.54]}` | 屏幕比例坐标。**只用于 `showAlertDialog` 弹出的系统对话框**，它们不在控件树里。先 `screenshot` 看清按钮位置，点完断言效果 |
| 输入 | `{"type": "127.0.0.1:5555"}` | 只支持 a–z、0–9、空格、`. , - / ; = : _` 和 `\b`（退格，例如清空搜索框：`"\b\b\b"`），不能输入中文 |
| 等待 | `{"wait": 2}` | 秒 |
| 截图 | `{"screenshot": "名字"}` | 同时保存控件树 |
| 列出元素 | `{"dump": "名字"}` | 见 4.2 |

**选择器**：`text`（全等）、`contains`、`id`、`a11y`、`a11yContains`、`placeholder`、`type`、`enabled`、`attrs`、`within`。可以组合，全部满足才算匹配。

同样的文字出现在两处时（例如侧栏的会话名和聊天里的消息），用 `within` 限定范围：`{"text": "hello", "within": {"id": "eta-conversation-list"}}`。没有合适的 id 就给容器加一个 `.id('eta-…')`。

`attrs` 按控件树的原始属性全等比较，例如“回复文字是透明的”：

```json
{"type": "Span", "contains": "这是预览数据", "attrs": {"fontColor": "#00000000"}}
```

**其他选项**：
- 某步失败后仍继续执行：加 `"continueOnFailure": true`；
- 深色模式或其他屏幕尺寸：在场景顶层写 `"screen": {"color": "dark"}` 或 `"screen": {"width": 1080, "height": 2340}`。

### 4.5 预览器做不到的事

| 局限 | 怎么办 |
| --- | --- |
| 不能输入中文 | 场景里输入英文和数字 |
| `bindPopup` 的气泡背景不绘制，只显示内容 | 背景、阴影只能真机看；放进真机检查点 |
| 系统接口是模拟的（数据库、ASSET、网络、窗口） | 场景使用 `FoundationPreview`：内存数据 + 假模型（`core/foundation/previewFixture.ts`）。新页面需要的演示数据加在这里，不要加进正式入口 |
| 依赖 `postFrameCallback` 的逐帧效果可能不推进 | 见任务 R4-1 |
| 不能操作其他应用、不能连接真实设备 | 手机操作功能用假后端写场景，真实效果放进真机检查点 |
| 系统对话框（`showAlertDialog`）不在控件树里 | 截图确认后用 `tapAt` 点按钮，再断言效果 |
| 没有 `taskpool`（返回空对象） | 依赖它的代码要有同线程兜底 |
| 预览器偶尔原生崩溃 | `run.sh` 自动重跑一次并在摘要注明；连续崩溃或有 JS 错误仍算失败，不要自己加重试 |

## 5. 卡住时

- 同一个问题认真尝试 3 次仍然不行，就停下：PR 保持草稿，写“阻塞报告”，内容包括：
  - 做了什么；
  - 完整的报错原文（不要转述）；
  - 怀疑的原因；
  - 需要谁做什么决定。
- **以下做法一律不允许**，发现即退回：
  - 删除或跳过测试；
  - 把失败的场景挪出 `tests/ui/`；
  - 修改检查脚本、误报列表或 `scripts/ui-preview/` 来让检查通过；
  - 加 `@ts-ignore`、`any`；
  - 把错误 `catch` 后吞掉不报。

  认为检查本身有错时，在 PR 里说明，由 Claude 判断。

## 6. 真机检查点

- 只有任务卡写了“真机检查点”的才请用户测，**不要每个 PR 都请用户测**。
- 到检查点时，写一份 `docs/device-runs/CHECKPOINT-<编号>.md`：
  - 开头写清用哪个分支或哪个提交编译；
  - 步骤不超过 15 步，每步写“操作 → 预期结果”；
  - 结尾放一张结果回填表：步骤 / 通过或失败 / 现象。
- 用户回报的结果原文记录在同一个文件里。之后按 4.1 先在预览器复现，再修。

## 7. PR 描述

按 AGENTS.md 的六项格式写，另外：
- 第 2 项（自动验证）直接贴 `dist/verify/summary.md`；
- 界面改动列出截图文件名；
- 修复类 PR 写明“预览器复现：能 / 不能（原因）”；
- 结尾贴 3.4 的自查清单。

## 8. Claude 怎么验收

每个 PR 按下面几项检查，结论是三种之一：
- **通过**；
- **小改后通过**：列出修改项；
- **退回**：列出必须修改的项，带编号。

| 检查 | 方法 |
| --- | --- |
| 范围 | diff 里只有任务卡的内容 |
| 自动检查 | CI 三个 Harmony 任务全绿，与贴出的摘要一致 |
| 界面 | Claude 在自己的环境检出分支，重跑 `npm run test:ui`，逐张看截图 |
| 场景质量 | 新场景断言了结果，覆盖任务卡列出的交互 |
| 规则 | 架构规则、移植来源注释、资源和 tokens、权限、密钥 |
| 文档 | 版本号、PROJECT_STATUS 已更新；没有冒充真机结果 |

被退回时，按编号逐条修改。在 PR 评论里逐条回复“已改：提交 xxx”，或者说明不改的理由。
