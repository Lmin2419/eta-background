# 后台机制与用户控制（0.4）

用户提供的轻启通知显示“正在运行定位任务，删除通知后任务将停止”。这说明它使用了定位类型持续任务通知，不能仅凭照片确定其内部定位实现。0.3 的开关只在下一轮手机任务开始时申请后台资源，不会立刻挂通知；这个交互容易被理解成已经开启服务，0.4 增加独立启动与真实状态显示。

## 启动方式

- **启动后台服务**：用户在设备页主动点击。申请成功后持续到用户停止、系统撤销/暂停、位置权限撤销或进程结束；单轮任务完成不会释放这个用户会话。聊天不依赖它，GUI 任务借用已有服务，不重复创建系统任务。
- **执行任务时自动申请**：用户未手动启动服务时，只在手机任务期间申请定位持续任务，完成后释放。这个偏好开关本身不启动定位或通知。
- **短时模式**：两者都没开启时，手机任务使用 `requestSuspendDelay`，额度到期停止。

不保存或自动恢复运行状态。重新打开助手/重启手机后须主动启动，不自动重挂被删除的通知。

## 申请与诊断

1. 前台检查本应用通知权限；未允许时通过系统弹窗申请，拒绝时明确提示。
2. 申请 `APPROXIMATELY_LOCATION` 并检查系统定位开关。
3. 注册系统取消/暂停回调，调用 `startBackgroundRunning(context, ['location'], wantAgent)`。
4. 订阅 `LOW_POWER` 大致位置更新，最小报告间隔 60 秒；回调不读取坐标字段，不保存、不打印、不上传，也不进入模型上下文。
5. 用 `getAllContinuousTasks` 回读系统任务，匹配返回的 continuousTaskId，排除暂停状态，然后显示任务 ID 和通知 ID。**API 确认不等于已目视验证通知样式**，仍需下拉通知栏核对。
6. 申请错误保留阶段与系统错误码，例如通知验证、定位订阅或持续任务校验失败。“检查系统状态”回读通知权限、定位开关与实际任务列表；“通知设置”打开系统设置。

系统位置开关关闭、权限撤销、持续任务取消/暂停都会通知使用该服务的手机任务停止，并取消设备请求与位置订阅。权限在进程仍存活时每 3 秒检查；系统也可能直接结束进程。

启动过程中停止或系统先取消再返回授权，不会在迟到结果到来后重新启动。资源释放失败会显示错误并阻止重复启动，用户需从系统设置停止应用后重开。

## 手机任务通知

参考 Eta 的任务状态生命周期，用鸿蒙 NotificationKit 独立实现。定位持续任务通知由系统管理，手机任务另有一张助手进度通知：

- 显示准备、思考、工具执行与暂停状态，只用通用状态文字，不把目标、回复、页面或密钥写到锁屏通知。
- “返回助手”打开会话并按已有接管逻辑暂停；“停止任务”打开助手并请求停止当前任务。
- 停止入口的 Want 携带当前进程生成的随机任务 nonce；仅匹配当前值才处理，外部 URI 不能提交任意任务/工具或停止后续新任务。任务结束清除 nonce。
- 完成/失败/停止后更新同一个任务通知为结果入口；系统是否横幅展示由其通知设置决定，不承诺小艺/流体云相同样式。
- 更新串行处理，进度约一秒合并一次；完成后不再发布迟到的运行状态。通知发送失败显示提示，不伪称已显示。

删除**系统定位任务通知**会结束服务；普通任务进度通知并不等同持续后台资格。用户可用其中的停止按钮结束单轮任务；若服务是手动启动，它保留到主动停止。通知内联回复、系统 Live View/胶囊与锁屏控制尚未实现。

## 边界

使用真实低功耗位置订阅进行开发验证，但通用 GUI 助手是否满足目标系统持续运行策略仍须实测；不承诺无限保活或上架资格，不自动改用其他后台类型。SDK 定义了 `SYSTEM_CANCEL_NOT_USE_LOCATION` 和业务不匹配等撤销原因。

不申请精确位置或 LOCATION_IN_BACKGROUND，不伪造定位、不隐藏通知。位置数据不提供给 Agent。后台运行与 HDC 授权是两个问题，出现定位通知不意味着可以关闭无线调试，也不增加后台虚拟屏或系统按键权限。
