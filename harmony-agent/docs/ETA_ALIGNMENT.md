# Eta → 鸿蒙普通权限版：功能对齐清单

审计日期：2026-10-29。参考 [Mangi-11/Eta](https://github.com/Mangi-11/Eta/tree/3019c43ce60cf53ebe1c2ba5ec86ec630830f39d)，固定提交 `3019c43ce60cf53ebe1c2ba5ec86ec630830f39d`。目标是普通用户持有的 Pura X Max / HarmonyOS 7：允许首次电脑签名安装、用户主动开启和授权无线调试；日常任务在手机执行，模型服务由用户自选。

**原则：能用普通应用能力或用户合法授权实现的功能纳入；需要系统签名、Root、Hook、企业管理身份或尚未取得的特殊资格的原始接口不做。可通过正常页面完成的任务，可以提供明确标识的 GUI 替代。** 不把“有同名 API”“编译通过”“能显示授权弹窗”当作已经取得权限。

本轮核对范围包括 README、技术/运行时/语音/角色/普通设备说明、设置与外观入口、15 份模型工具目录和子任务目录、工具权限投影、Phone/PersonalSearch 动态条目。逐项表覆盖 **129 个工具目录/权限登记条目，包含兼容别名和运行时工具，并非 129 个同时可用的工具**。没有声称审阅全部源代码的每一行，也没有真机验证上游全部功能。

- [129 项工具逐项对照 CSV](ETA_TOOL_INVENTORY.csv)：每项的 Eta Root 条件、鸿蒙路线、决定、实际开发状态和源码链接。
- [审阅来源与内容哈希](ETA_AUDIT_SOURCES.json)：固定版本，方便后续追踪变更。
- [鸿蒙 SDK 权限证据](HARMONY_PERMISSION_EVIDENCE.json)：SDK 26.0.0.105 中的权限定义摘录；目标手机仍需确认实际 API 版本和授权行为。

## 权限边界

| 层级 | 本项目采用的边界 |
| --- | --- |
| 普通应用自身能力 | 网络、应用沙箱、ArkUI/ArkWeb、模型调用、会话与记忆、用户导入的内容。可以实现。 |
| 普通用户授权 | 系统选择器提供的文件/图片/联系人；正常可申请的麦克风、位置、应用范围日历等。按实际授权范围实现。 |
| 用户授权无线调试 | 本机 HDC/UITest 执行器。属于调试会话权限，不等于 App UID，也不等于 Root；已写原型，需目标手机验证。 |
| 特殊权限资格 | `system_basic/system_core`、ACL/provision 资格、SYSTEM/MDM 接口不作为普通侧载应用的默认能力。若普通个人开发者的合法调试签名确实可获得某项非 SYSTEM 权限，验证后纳入。即使 `grantMode=user_grant` 或 `availableType=NORMAL`，仍须检查权限等级和资格。 |
| 厂商私有数据/系统注入 | 不移植 ColorOS DMP、小布/小爱 Hook、其他 App 数据库、Magisk/LSPosed、全局助理替换等实现。 |

SDK 中值得单独区分的项目：

| 能力 | SDK 证据 | 决定 |
| --- | --- | --- |
| 位置/麦克风 | `APPROXIMATELY_LOCATION`、`MICROPHONE` 为 `normal + user_grant` | 可以纳入；模型位置工具与后台模式分开授权、分开用途。 |
| 日历 | `READ_CALENDAR/WRITE_CALENDAR` 为 normal；`READ_WHOLE_CALENDAR/WRITE_WHOLE_CALENDAR` 为 system_basic | 先支持应用可访问的日历/事件及用户确认创建，不承诺全量系统日历。`getAllCalendars` 文档明确当前应用创建的及默认日历对象。 |
| 全量联系人/图片/剪贴板 | `READ_CONTACTS`、`READ_IMAGEVIDEO`、`READ_PASTEBOARD` 为 system_basic | 先做选择器、分享导入和用户主动粘贴；不把这些交互改称全量后台读取。 |
| 通知监听 | `SUBSCRIBE_NOTIFICATION` 为 system_basic；扩展订阅接口还注明蓝牙设备订阅场景 | 当前普通权限范围不做全局通知收集器。自身任务通知可以做；用户提供的通知文本可分析。 |
| 应用使用统计/全应用列表 | `BUNDLE_ACTIVE_INFO`、`GET_INSTALLED_BUNDLE_LIST` 为 SYSTEM/system_basic | 不默认开放对应原生接口。全应用目录可另测已授权 HDC 查询；使用统计不作可交付承诺。 |
| 无障碍/静默截图/浮窗 | `ACCESSIBILITY_EXTENSION_ABILITY` 为 SYSTEM/system_basic，`CAPTURE_SCREEN` 为 system_core，`SYSTEM_FLOAT_WINDOW` 为 system_basic | 不照搬安卓无障碍和悬浮窗假设。GUI 走已授权调试路线；其他入口按系统公开能力另测。 |

SDK 定义与开发者调试签名、商用上架资格不是同一层。本清单不把所有 system_basic 权限断言为永久不可得，也不通过改签名等级获取权限：具体 ACL 是否能由普通个人调试签名合法取得，需要用户自己的签名工程和设备验证。已经能证明只属于 SYSTEM/系统签名或厂商私有实现的原接口排除；尚未确认资格的接口不算已可用。用户授权 HDC 能读取的有限信息也须单独实测，不能从 App UID 的限制推断调试 shell 的全部边界。

## 开发顺序与验收

1. **底座和模型（当前）**：完成 BYOK 多配置/诊断/安全存储；目标机验证本机 HDC、UITest、折叠屏坐标、输入和后台取消。无线调试尚未验证前，不声称整机助手已经稳定可用。
2. **聊天与任务体验**：会话历史、消息/步骤时间线、多轮与附件、模型切换、流式、补充指令、权限/工具页和用户接管。界面结构借鉴 Eta，使用 ArkUI 实现，不复制 Android 组件。
3. **无特殊系统权限的能力**：网页/浏览器、工作区、长期记忆、Skills、MCP、子任务、角色、语音，分别带取消、超时和资源清理。
4. **普通授权与 GUI 场景**：选择器导入、限定日历、位置、公开设备信息；补足手势、应用查询与条件等待，再覆盖系统设置/闹钟/便签等 GUI 任务。
5. **只验证、不预先承诺的部分**：其他模型协议的具体服务差异、订阅登录资格、健康数据、通用终端/PRoot、特殊入口及无线调试关闭后的 worker。确认有普通用户可行路线才进入产品。

实现状态必须经过“代码完成 → 自动化/编译验证 → 目标机授权与实测”推进。没有权限的工具不发布给模型；权限撤销或系统取消后停止使用；GUI 替代只能报告页面上实际核对的结果。上游 README 与旧技术文档存在不一致的地方（如日历与 PRoot），本清单优先采用同提交的能力注册代码，并在鸿蒙端重新确认。
