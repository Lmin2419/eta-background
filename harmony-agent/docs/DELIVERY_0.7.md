# 随身助手 0.7 落地核验包

本包用于在你自己的 Pura X Max 上覆盖升级和核验，不是已通过全部真机验收的稳定版。构建与测试结果见 `验收资料/VALIDATION_0.7.json`。

## 已有签名工程：优先使用升级包

1. 备份原 DevEco 工程，并导出重要会话。**不要卸载手机上的旧助手。**
2. 将 `安装工程/harmony-agent-0.7.0-upgrade.zip` 解压到原工程根目录，合并并覆盖同名文件。展开后应直接看到 `entry`、`AppScope`，不要多套一层目录。
3. 升级包不覆盖根目录和 entry 的构建配置，因此保留你的签名设置与预编译原生库。包名默认仍为 `com.example.harmonyagent`；如果你自己改过包名，保留原 `AppScope/app.json5`，只更新 `versionCode` 为 `70000`、`versionName` 为 `0.7.0`。
4. 在 DevEco 同步工程，选择已连接的手机，使用原签名点击 Run 覆盖安装。SDK 使用 API 26。若提示签名缺失，检查原工程 `app.products[].signingConfig` 是否仍指向自己的签名配置；升级无需更换证书。
5. 打开应用后先检查原会话和模型配置，再到设置的备份恢复入口导出备份。按照 `验收资料/ACCEPTANCE_0.7.md` 核验，结果可以填到 `DEVICE_ACCEPTANCE_RECORD_0.7.csv`。

## 包内文件

- `安装工程/*-upgrade.zip`：现有工程覆盖升级，首选。
- `安装工程/*-deveco.zip`：带 ARM64 预编译库的完整工程。需要重新打开完整工程时使用，仍须生成自己的签名；不要把它自带的空签名配置覆盖到原工程。
- `源码/*-source.zip`：完整源码，包括原生构建脚本、测试和实施文档。
- `验收资料/IMPLEMENTATION_STATUS_0.7.csv`：全部 83 项的实现状态、源码路径、测试证据和剩余边界。
- `验收资料/IMPLEMENTATION_PROGRESS_0.7.md`：本轮落实范围。
- `验收资料/ACCEPTANCE_0.7.md`、`DEVICE_ACCEPTANCE_RECORD_0.7.csv`：24 项真机/服务/数据核验操作与填写表。
- `验收资料/ETA_PARITY_IMPLEMENTATION_PLAN.md`：原实施方案，保留章节与依赖关系。
- `验证记录/`：本轮实际类型检查、161 项测试、8 项原生检查、API 26 构建、独立导出工程构建和产物检查记录。
- `SHA256SUMS`：本落地包各文件的校验值；可用于确认传输没有损坏。

## 优先核验你之前遇到的问题

先测试“模型目录获取和四项诊断不清空表单”，再测“聊天长回复、流式输出、滚动、键盘和折叠”。随后验证通知控制、删除后不复活、通知续聊、断连后停止，最后再测试扩展和备份恢复。失败时保留清单编号、提示文字与截图，便于定位同一问题。

## 能力边界

本轮已经实现更多 ArkUI 页面与运行逻辑，但没有真实手机、模型服务、长期后台资格的完整验收结果。虚拟屏、长按电源键替换、LiveView 和关闭无线调试后的继续执行仍属条件项。普通通知不能替代后台运行资格；不能仅凭编译成功判断后台已稳定。

备份不含模型或 MCP Key、HDC 身份和后台授权；恢复后要重新填写或授权。语音依赖系统离线能力，角色 PNG 导出使用一像素封面，浏览器只操作助手自己的 Web 视图。详细限制见 `UPGRADE_0.7.md`。
